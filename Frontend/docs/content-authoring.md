# MDX에 글·이미지·코드·실습 배치하기

본문 `.mdx`에 작성한 순서가 화면 순서입니다. [강의 생성 안내](../src/content/README.md)와 [복사할 템플릿](../src/content/templates/new-lesson.mdx)을 먼저 참고하세요.

## 글 → 이미지 → 글 → 코드 → 이미지

````mdx
## 학습 상태 복구

먼저 문제를 설명합니다. **중요한 내용**을 강조할 수 있습니다.

![계층 비교](/images/container-layers.svg)

이미지를 해석하는 설명을 이어 씁니다.

```python
print("checkpoint loaded")
```

<Figure
  src="/images/container-layers.svg"
  alt="가상 머신과 컨테이너의 계층 비교"
  caption="이미지 아래에 표시할 설명"
/>
````

사진·그림은 `public/images/`에 넣고 `/images/파일명`으로 참조합니다. PNG·JPG·WebP·SVG 또는 지속적으로 접근 가능한 HTTPS 이미지 주소를 사용합니다. 출처가 필요하면 Figure에 `sourceTitle`, `sourceUrl`을 함께 지정합니다. 이미지는 원본 보기와 로딩 실패 안내를 제공하고 코드 블록은 복사 버튼을 제공합니다. 코드의 문법 색상 강조는 현재 제공하지 않습니다.

일반 Markdown의 목록·인용·링크와 GFM 표도 사용할 수 있습니다. 코드 밖에서 `<`, `{` 등을 문자 그대로 쓰려면 `&lt;`, `&#123;`처럼 이스케이프하거나 인라인 코드로 감싸세요.

## 배치할 수 있는 실습

| 태그                                          | 동작                                         | 필요한 설정                             |
| --------------------------------------------- | -------------------------------------------- | --------------------------------------- |
| `<NodeExample />`                             | 완성 흐름 추적·빠진 연결 수정·자료 전달 확인 | 같은 강의 설정의 `nodeExample`          |
| `<Activity />`                                | 기존 비교·예측 시뮬레이션을 접어서 표시      | 같은 강의의 `activity`와 관련 모형 설정 |
| `<Activity open />`                           | 시뮬레이션을 펼쳐 표시                       | 위와 동일                               |
| `<Question ... />`                            | 독립 선택형 연습과 즉시 해설                 | MDX의 문항 속성                         |
| `<Reveal title="해설">...</Reveal>`           | 해설을 접었다 펼치기                         | 자식 본문                               |
| `<Callout title="참고">...</Callout>`         | 참고 설명 강조                               | 자식 본문                               |
| `<Quiz />`                                    | 기존 강의 이해 확인·완료 처리                | 같은 강의의 `assessment`                |
| `<WorkflowLab lessonId="feature-workflow" />` | 기존 종합 실습 삽입                          | `workflow`가 있는 강의 ID               |

MDX는 기존 React 실습을 원하는 위치에서 사용하는 수단입니다. 새로운 실습의 계산·실행 동작은 React 컴포넌트로 구현한 뒤 `src/learning/LessonMdx.tsx`의 컴포넌트 목록에 등록해야 합니다. Python·셸 코드 블록은 읽고 복사하는 예제이며 실행되지 않습니다. WorkflowLab은 지정한 기존 종합 실습의 진행 기록을 공유합니다.

### Activity 종류 추가하기

기존 `<Activity />` 안에서 다른 조작 방식을 제공할 때는 MDX 컴포넌트를 새로 등록하지 않습니다. 공통 프레임은 유지하고 종류별 본문만 교체합니다.

| 파일 | 책임 |
| --- | --- |
| `src/activities/Activity.tsx` | 펼침·접힘, 제목, 교육용 모형 안내와 본문 배치 |
| `src/activities/activityRegistry.ts` | 활동 종류와 본문 컴포넌트·안내 문구 연결 |
| `src/activities/MachineActivity.tsx` | EC2와 프로그램 실행 상태 조작 |
| `src/activities/VirtualActivity.tsx` | 앱 수에 따른 VM·컨테이너 구조 비교 |
| `src/activities/SimulationActivity.tsx` | 기존 설정 기반 시뮬레이션의 재생·결과·기록 |

새 활동 본문은 `ActivityViewProps`의 `lesson`과 `spec`을 입력으로 받을 수 있습니다. 상태와 조작 로직은 해당 본문에서 관리하고, 공통 제목이나 펼침 틀을 다시 만들지 않습니다. `ActivityKind`에 종류를 추가하고 `activityRegistry.ts`에 본문과 문구를 등록하면 강의 렌더러를 수정하지 않고 `<Activity />`에서 선택합니다. 별도 등록이 없는 기존 종류는 `SimulationActivity`를 재사용합니다.

### 본문 연습 문제

```mdx
<Question
  id="checkpoint-age"
  question="80단계에서 중단되고 70단계 체크포인트만 있다면?"
  options={['70단계 상태에서 이후 계산 재실행', 'AMI로 80단계 메모리 복원']}
  correct={0}
  explanation="저장되지 않은 계산은 다시 수행해야 합니다."
/>

<Reveal title="해설 더 보기">

자주 저장하면 손실되는 계산은 줄지만 저장 비용은 늘어납니다.

</Reveal>
```

정답 번호는 0부터 시작합니다. 문항 `id`는 같은 강의 안에서 고유하게 유지하세요. 답변은 강의별·문항별로 저장되며 새로고침 후 복원됩니다. 이 연습으로 강의가 완료되지는 않습니다. 필수 평가는 `<Quiz />`로 별도 배치합니다. 방문 횟수와 실습 조작 횟수도 완료로 간주하지 않습니다.

### 노드 예제

기존 [DVC 설정](../src/content/lessons/04-reproducibility/dvc-restore.lesson.ts)의 `nodeExample`을 참고하세요. 노드·연결·전달 자료·실패 영향·질문을 정의하고 본문의 원하는 곳에 `<NodeExample />`를 넣습니다. 위치 인덱스를 계산할 필요가 없습니다.

여러 예제가 필요하면 `<NodeExample spec={...} />`로 각각 전달할 수 있습니다. 각 spec의 `id`는 서로 달라야 저장 기록이 분리됩니다. 긴 구성은 별도 TypeScript 파일에서 export한 뒤 MDX에서 import해도 됩니다. 실제 노드 예제가 있는 문서는 컴파일 시 목차에 표시됩니다.

`nextLesson`은 선택 사항입니다. 관련 종합 실습이 있는 경우에만 해당 강의 ID를 지정하세요. 생략하면 하단의 종합 실습 안내 문구와 이동 링크를 표시하지 않습니다.

## 기본 문서 요소

`<LessonSummary />`, `<Reflection />`, `<AdvancedReadings />`, `<References />`는 설정 파일의 정리·질문·심화 읽기·출처를 표시합니다. 필요한 위치로 이동할 수 있고 일반 Markdown으로 직접 대체할 수도 있습니다. 심화 읽기는 기본 완료 조건에 포함되지 않습니다.

`##` 제목과 본문·표·코드·이미지는 검색용 색인에도 반영됩니다. 색인은 기존 화면과의 호환용이며 문서의 자유로운 배치를 제한하지 않습니다. 외부 API와 문서 편집기는 추가하지 않습니다.

## 레슨 편집 기준

모든 레슨의 첫 문제 제기 직후에는 첫 질문을 떠올릴 이미지를 배치하고, 이어지는 문단에서 그림 속 대상을 짚어 설명합니다. 내부 구조나 자료 전달을 설명할 때는 추가 도식을 사용합니다. 전달 화살표에는 이동하는 자료를 쓰고, 비교·구성 관계와 구분합니다. 직접 만든 그림은 `public/images/lessons/폴더/강의-ID/`에 보관합니다. [53개 레슨 편집표](lesson-editorial.md)를 참고하세요.

```mdx
<LessonSummary>

학습 데이터와 결과 모델을 다시 사용하려면 저장할 곳이 필요합니다. S3의 버킷과 객체 키로 파일을 식별하고 EC2가 데이터를 읽어 계산한 뒤 결과 모델을 저장합니다. 추론 프로그램은 보관한 모델을 읽어 요청에 응답합니다.

- 입력·코드·모델의 버전을 연결해 두면 어떤 실행에서 나온 결과인지 다시 찾을 수 있습니다.

</LessonSummary>
```

핵심 정리는 필요성 → 동작과 자료의 흐름 → 결과의 활용 또는 판단 기준을 연결한 문단과 목록으로 씁니다. 위처럼 본문을 넣으면 MDX 내용이 표시됩니다. 기존 빈 태그는 설정의 `caution`을 표시하는 호환 형식입니다. 새 강의에서는 MDX에 핵심 정리를 작성하세요.

강조는 중요한 용어와 차이에, 콜아웃은 판단 조건이나 여러 단계의 흐름에 사용합니다. 인용은 학습자의 질문이나 출처가 있는 원문을 구분할 때 씁니다. 명령·YAML은 실행 전후에 바뀌는 상태를 설명하고, 노드 실습 전후에는 예측 질문과 전달 자료 해석을 둡니다.
