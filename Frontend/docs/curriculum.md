## 기본·심화·평가

모든 기본 강의는 문제·원리·흐름·한계·전체 맥락을 설명합니다. 기존 개념의 고유 설명과 비교표를 유지하며 독립된 설명과 상황형 평가를 추가했습니다. CSI·JuiceFS, 테이블 커밋, CUDA 메모리 계층, GPU 배치, Prometheus TSDB는 심화 읽기에 보존합니다. 심화와 비교 활동은 필수 완료 조건이 아닙니다.

7주차의 미작성 본문은 gRPC·Prometheus·OpenTelemetry와 기존 강의의 공식 출처를 근거로 보충합니다. HTTP·gRPC는 통신 방식, Batch·Real-time은 처리 시점입니다. Data Drift와 Concept Drift를 구분하고 정답 수집의 지연과 조사 후 재평가를 설명합니다.

## 정확성·교육용 경계

| 항목      | 적용 기준                                                                 |
| --------- | ------------------------------------------------------------------------- |
| DVC       | .gitignore와 .dvcignore 분리, 캐시 부재 시 원격 조회, 선언된 의존성 기준  |
| 스토리지  | RWO는 단일 노드이며 다중 Pod 가능, 공유 읽기에 무조건 RWX를 요구하지 않음 |
| 벡터 검색 | PostgreSQL의 pgvector·HNSW 지원 포함, ANN의 재현율·지연 비교              |
| GPU       | 데이터 병렬은 모델 복제, 혼합 정밀도가 전체 메모리 절반을 보장하지 않음   |
| RAG       | 동일 차원만으로 공간 호환 보장하지 않음, 검색과 생성의 오류 분리          |
| 피처      | 정의·예측 시점·갱신 지연을 검증, 도구 도입이 누출을 자동 제거하지 않음    |
| 배포      | Shadow의 응답은 사용자에게 보내지 않음, 승격은 별도 판단                  |
| 관측      | 지표·로그·트레이스 분리, 알림은 자동 재학습·배포 명령이 아님              |

활동의 수치·고정 응답은 교육용 모형이며 실제 도구 실행이 아닙니다. 기존 계산 가정은 각 활동의 설명과 테스트에서 유지합니다. 종합 예시는 학습 80개·평가 20개, 예시 정확도 0.85를 사용합니다.

## 검증

콘텐츠·출처·지도 목적지·필수 활동 없는 완료·오답 차단·실습의 자료 전달·실패 전파·과거 저장 격리·새 기록 복원·모바일 읽기를 자동 검사합니다. 실제 학습 효과는 새로운 사례의 설명과 선택 이유를 사전·사후 대조해야 하며 아직 참여자 측정은 수행하지 않았습니다.

## 본문 노드 예제 배치

단원 마지막의 종합 실습 전에 다음 11개 개념 강의의 설명 중간에 작은 노드 예제를 제공합니다.

| 강의                 | 확인할 관계                                |
| -------------------- | ------------------------------------------ |
| S3 객체              | 객체 읽기 → EC2 학습 → 모델 보관           |
| 이미지·컨테이너      | 같은 이미지에서 실행되는 두 컨테이너       |
| Kubernetes 제어·요청 | 원하는 실행 상태와 사용자 요청의 별도 경로 |
| PV·PVC               | Pod의 참조와 PVC·PV의 바인딩               |
| DVC 복원             | 메타데이터·원격·캐시·작업 파일             |
| DVC 파이프라인       | 학습 입력·모델·별도 평가 자료의 의존성     |
| 데이터 병렬          | 복제된 모델에서 계산한 두 기울기의 동기화  |
| Feature Store        | 과거 학습 조회와 현재 추론 조회            |
| RAG                  | 질문 벡터·문서 색인 → 검색 → 생성 근거     |
| Canary               | 기존·새 모델로 전달되는 실제 사용자 요청   |
| 관측 후 개선         | 관측 → 조사 → 후보 평가 → 배포 판단        |

예제는 완성 흐름 추적 → 빠진 연결 채우기 → 이유 확인 → 관련 종합 실습으로 이어집니다. 기본 캔버스 높이는 600px이며 840px로 펼칠 수 있습니다. 새 강의 주소나 강의 수는 추가하지 않고 기존 본문에 삽입합니다.
