## 문제 상황과 전체 맥락

EC2에서 학습 코드를 실행하려면 입력 데이터가 필요하고, 실행이 끝난 뒤에는 모델 파일을 보관해야 합니다. 실행할 컴퓨터와 별도로 파일을 저장하고 다시 읽을 곳이 필요합니다. 이 강의에서는 그 역할을 하는 S3를 살펴봅니다.

## 개념 이해

S3는 **Simple Storage Service**의 약자입니다. **객체 스토리지 서비스**라는 의미입니다. 풀어서 설명하면, 데이터를 객체 단위로 보관하는 저장소라고 할 수 있습니다.

S3 안에는 버킷이 존재합니다. 버킷은 객체를 담는 공간입니다. 앞에서 데이터는 **객체** 단위로 보관된다고 설명했습니다. 버킷은 여러 객체들이, 다시 말해 데이터들을 특정한 단위로 만들어서 보관하는 공간이라고 할 수 있습니다.

<Figure
  src="/images/lessons/00-overview/s3-objects/s3-buckets.jpg"
  alt="버킷 안에 여러 객체가 담겨 있고 그중 한 객체를 확대해 보여 주는 그림."
  caption="버킷과 객체 키를 연결해 파일을 식별합니다."
/>

버킷 안에는 여러 객체들이 담길 수 있습니다. 객체 키는 버킷 안에서 객체를 식별하는 이름입니다. 예를 들어 `blockml-study` 버킷의 `datasets/reviews.csv` 키로 학습 데이터를 구분할 수 있습니다.

객체를 업로드하면 저장하고, 객체를 조회하면 내용을 읽습니다. S3는 저장된 Python 코드를 실행하거나 모델을 스스로 학습시키지 않습니다. 데이터를 읽고 계산하는 역할은 EC2에서 실행하는 프로그램이 담당합니다.

> **연결 전에 예측하기** — S3 객체가 스스로 학습하는 것이 아닙니다. 저장된 데이터를 읽는 작업과 결과를 보관하는 경로를 따라가 보세요.

<NodeExample />

연결을 따라가며 확인한 자료는 **train-v1.csv · model-v1**입니다. 추론 프로그램은 보관한 모델 파일을 다시 읽어 사용합니다. 어떤 데이터와 코드로 만든 모델인지도 함께 기록해야 나중에 실험을 되짚을 수 있습니다.

## 관찰한 결과 해석하기

리뷰 파일을 S3에 업로드 → EC2의 학습 프로그램이 파일 읽기 → 학습 결과 생성 → 모델 파일을 S3에 업로드 순서로 따라가 보세요. 학습 데이터와 결과 모델은 서로 다른 객체 키로 구분할 수 있습니다. 저장했다는 사실만으로 어떤 데이터와 코드로 만든 모델인지 자동으로 기록되지는 않습니다.

## 적용 조건과 한계

프로그램이 객체를 읽으려면 버킷과 키를 알아야 하고, 요청을 보낼 경로와 접근 권한도 필요합니다. 프로그램에서는 버킷과 키를 지정해 객체를 읽고 씁니다. S3의 객체를 일반 디스크 파일과 완전히 같은 방식으로 다룬다고 가정하지 마세요. 여기서는 업로드와 조회의 역할부터 이해합니다.

## 전체 과정과 연결하기

이전에 EC2에 대해서 배웠습니다. EC2가 실행을 담당한다면, S3는 저장을 담당합니다.

<Callout title="흐름">

> 1. S3의 학습 데이터를 EC2가 읽습니다.
> 2. EC2 안에서 학습 데이터를 사용해서 작업을 수행합니다.
> 3. 작업 결과 파일을 S3에 보관합니다.

</Callout>

이렇게 저장된 결과를 추론 프로그램이 다시 읽어 사용할 수 있습니다. 이 구분은 이후 컨테이너, 데이터 버전 관리, 모델 배포를 배울 때도 유지됩니다.

<LessonSummary>

리뷰 분류 모델에는 EC2가 읽을 입력 데이터와 학습 뒤 모델을 보관할 곳이 필요합니다. S3의 버킷과 객체 키로 각 파일을 찾고, EC2가 입력을 읽어 계산한 뒤 결과 키에 모델 파일을 저장합니다.
