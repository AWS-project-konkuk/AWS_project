## 저장소와 커밋

**Git**은 코드의 변경 이력을 관리하는 도구입니다. **저장소**에는 프로젝트 파일과 이력이 들어 있습니다. 변경 사항을 골라 **커밋**하면 그때의 파일 상태가 메시지와 함께 기록됩니다.

| 예시 커밋 ID | 그때의 `count_rows.py`     |
| ------------ | -------------------------- |
| `a1b2c3d`    | 리뷰를 모두 셉니다.        |
| `d4e5f6a`    | 빈 리뷰를 제외해서 셉니다. |

작업 결과 옆에 커밋 ID를 남겨 두면, 나중에 해당 커밋에서 실행한 코드를 찾을 수 있습니다.

## Git과 GitHub

**Git**은 내 컴퓨터에서도 저장소와 이력을 관리할 수 있습니다. **GitHub**는 Git 저장소를 인터넷에 올려 팀원과 공유할 수 있는 서비스입니다.

## 자주 쓰는 Git 명령어

저장소와 커밋을 다룰 때 가장 자주 쓰는 명령어입니다.

| 목적             | 명령어                   | 하는 일                                       |
| ---------------- | ------------------------ | --------------------------------------------- |
| 변경 상태 보기   | `git status`             | 수정한 파일과 다음 커밋에 담을 파일을 확인    |
| 변경 내용 비교   | `git diff`               | 아직 담지 않은 파일의 변경 내용을 확인        |
| 커밋에 담기      | `git add <파일>`         | 다음 커밋에 넣을 변경을 고름                  |
| 커밋 만들기      | `git commit -m "메시지"` | 고른 변경을 메시지와 함께 기록                |
| 커밋 목록 보기   | `git log --oneline`      | 커밋 ID와 메시지를 한 줄씩 확인               |
| 저장소 내려받기  | `git clone <주소>`       | GitHub 등의 저장소를 내 컴퓨터로 복제         |
| 내 커밋 올리기   | `git push`               | 내 커밋을 GitHub 같은 원격 저장소로 전송      |
| 최신 변경 받기   | `git pull`               | 원격 저장소의 새 커밋을 내려받아 합침         |

`git log --oneline`에서 보이는 짧은 ID(`a1b2c3d` 등)가 앞에서 본 커밋 ID입니다.

<LessonSummary>

Git 저장소에는 프로젝트 파일의 변경 이력이 쌓입니다. 커밋은 선택한 변경을 기록하며 커밋 ID는 그때의 코드 버전을 찾는 데 쓰입니다. MLOps 작업에서는 실행 결과와 함께 코드의 커밋 ID를 남겨 두면 이름이 같은 파일 중에서도 어떤 버전으로 작업했는지 추적할 수 있습니다.

</LessonSummary>
