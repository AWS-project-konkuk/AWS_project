## MLOps는 무엇인가요?

**MLOps(Machine Learning Operations)는 머신러닝 모델의 개발부터 배포와 운영까지, 전체 과정을 일관되게 관리하고 반복할 수 있도록 만드는 방법과 실천입니다.** 데이터 준비와 모델 학습뿐 아니라 실행 환경, 버전 관리, 평가, 배포, 운영 중 품질 확인까지 함께 다룹니다.

이 과정의 목표는 **모델을 서비스로 제공하는 데 필요한 구성 요소를 이해하고, 이들이 어떻게 연결되는지 설명하는 것**입니다. 먼저 전체 지도를 살펴보고, 뒤의 단원에서 각 부분을 하나씩 배웁니다.

## 왜 모델 학습 외에 배울 것이 있나요?

모델이 리뷰를 긍정과 부정으로 잘 분류하더라도, 다른 컴퓨터에서 실행되지 않거나 사용자가 접근할 수 없다면 서비스로 쓰기 어렵습니다. 어떤 데이터로 만든 모델인지 모르면 문제가 생겼을 때 원인을 찾기도 어렵습니다. 운영을 시작한 뒤에는 새로 들어오는 리뷰의 특성이 달라져 예측 품질이 떨어질 수도 있습니다.

따라서 모델의 정확도와 함께 **어디서 실행할지, 무엇을 기록할지, 어떻게 제공하고 확인할지**를 다뤄야 합니다. MLOps에서는 모델 개발자와 데이터·서비스·인프라 담당자가 이 과정을 함께 관리합니다.

| 모델을 만들 때의 질문      | 서비스로 운영할 때 추가되는 질문                         |
| -------------------------- | -------------------------------------------------------- |
| 어떤 데이터로 학습할까?    | 그 데이터와 코드의 버전을 나중에도 찾을 수 있을까?       |
| 평가 결과가 얼마나 좋은가? | 운영에서도 예측 품질을 어떻게 확인할까?                  |
| 내 컴퓨터에서 실행되는가?  | 다른 환경에서도 실행하고 사용자 요청을 처리할 수 있을까? |
| 새 모델이 더 좋은가?       | 기존 서비스를 유지하면서 어떻게 교체하고 되돌릴까?       |

## 먼저 알아둘 기본 용어

지금은 다음 용어의 역할만 구분하면 됩니다. 구체적인 구성 방법과 도구는 관련 단원에서 배웁니다.

| 용어                 | 의미                                                                    |
| -------------------- | ----------------------------------------------------------------------- |
| 학습(Training)       | 데이터에서 패턴을 배워 모델을 만드는 과정                               |
| 평가(Evaluation)     | 학습에 사용하지 않은 자료 등으로 모델이 목적에 맞는지 확인하는 과정     |
| 추론(Inference)      | 학습된 모델에 새 입력을 넣어 예측을 얻는 과정                           |
| 배포(Deployment)     | 선택한 모델과 프로그램을 사용할 환경에 반영하는 작업                    |
| 서빙(Serving)        | 모델을 이용해 다른 프로그램이나 사용자에게 예측 결과를 제공하는 일      |
| 파이프라인(Pipeline) | 데이터 준비·학습·평가 같은 작업을 입력과 출력의 관계에 따라 연결한 흐름 |
| 모니터링(Monitoring) | 운영 중인 시스템과 모델의 상태를 지속해서 관찰하는 일                   |

큰 흐름은 **데이터 준비 → 학습 → 평가 → 배포 → 서빙 → 모니터링**입니다. 운영에서 발견한 문제는 다음 데이터 수정이나 모델 개선의 근거가 됩니다. 사용자의 예측 요청은 배포한 모델로 처리하며, 요청이 올 때마다 모델을 처음부터 학습하지는 않습니다.

## MLOps의 핵심 개념

MLOps는 특정 제품 하나의 이름이 아닙니다. 여러 도구를 사용하더라도 다음 질문에 답할 수 있어야 전체 과정을 관리할 수 있습니다.

| 핵심 개념            | 확인할 질문                                            | 이 과정에서 연결되는 학습                |
| -------------------- | ------------------------------------------------------ | ---------------------------------------- |
| 재현성과 버전 관리   | 어떤 코드·데이터·환경으로 이 모델을 만들었는가?        | Docker, Git·LFS·DVC, 데이터 시점 관리    |
| 작업 연결과 자동화   | 입력이 바뀌면 어떤 작업을 다시 수행해야 하는가?        | 파이프라인의 의존성과 실행 순서          |
| 검증과 배포 관리     | 새 모델을 서비스에 반영할 근거와 되돌릴 방법이 있는가? | 모델 평가, 배포 방식, 버전 전환          |
| 관측과 지속적인 개선 | 서비스가 정상적으로 응답하고 예측도 유효한가?          | 지표·로그·트레이스, 모델 품질과 드리프트 |

자동화와 관련해서는 **CI(지속적 통합)**, **CD(지속적 전달·배포)**, **CT(지속적 학습)**라는 말도 사용합니다. 각각 변경 사항의 검증, 배포 준비와 반영, 새 데이터 등을 이용한 반복 학습을 뜻합니다. 이 과정에서는 이런 흐름을 이해하는 데 필요한 구성 요소와 연결 관계부터 배웁니다.

<Callout title="자동화에도 판단 기준이 필요합니다">

작업을 자동으로 실행하려면 입력, 실행 조건, 성공 기준을 먼저 정해야 합니다. 품질 경고가 발생했다고 새 모델을 바로 배포하는 것이 아니라, 원인을 조사하고 개선한 모델을 평가한 뒤 반영 여부를 결정합니다.

</Callout>

## 앞으로 무엇을 배우나요?

과정은 **0~9단원**으로 구성되어 있습니다. 실행과 저장의 기초를 익힌 뒤 데이터·학습·서비스 운영으로 범위를 넓히고, 마지막에는 배운 내용을 하나의 흐름으로 연결합니다.

| 단원                          | 배울 내용                                                    | 학습 후 설명할 수 있는 것                                  |
| ----------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 0. 전체 흐름과 EC2·S3 기초    | MLOps의 범위, EC2의 실행 자원, S3의 파일 보관                | 코드를 실행하는 컴퓨터와 데이터를 저장하는 공간의 역할     |
| 1. 같은 환경에서 실행하기     | 컨테이너와 Docker 이미지, Kubernetes의 실행 관리와 요청 전달 | 같은 실행 환경을 준비하고 서비스를 유지하는 방법           |
| 2. 데이터를 보존하고 공급하기 | 스토리지 종류, 데이터 수명, PV·PVC, 데이터 공급 병목         | 실행이 끝나도 보존할 데이터와 학습에 필요한 저장 방식      |
| 3. 같은 실험으로 돌아가기     | Git·LFS·DVC, 파이프라인, 데이터 버전과 시점                  | 과거 실험의 코드와 데이터를 찾아 다시 실행하는 방법        |
| 4. GPU로 학습하기             | CPU·GPU, CUDA, GPU 메모리 부족, 병렬 학습                    | 학습에 필요한 자원과 메모리·연산·통신의 관계               |
| 5. 학습과 추론의 피처 맞추기  | 모델 입력에 쓰는 피처의 정의, Feature Store, 조회 시점       | 학습과 실제 예측에서 입력의 의미와 시간 기준을 맞추는 방법 |
| 6. 문서를 검색해 답변하기     | 임베딩, 벡터 검색, ANN·HNSW, RAG                             | 질문과 관련된 문서를 찾아 답변의 근거로 전달하는 흐름      |
| 7. 모델을 제공하고 교체하기   | 통신 방식, 일괄·실시간 예측, Blue·Green·Canary·Shadow 배포   | 예측을 제공하는 방식과 새 모델을 검증·전환하는 방법        |
| 8. 운영 상태를 보고 개선하기  | 지표·로그·트레이스, Prometheus, 모델 드리프트                | 시스템 이상과 모델 품질 변화를 조사하고 개선하는 과정      |
| 9. 전체 과정 설명하기         | 피처·검색 응용과 전체 파이프라인 종합                        | 데이터부터 운영까지 연결하고 문제의 영향을 추적하는 방법   |

## 학습은 어떻게 진행하나요?

**설명 읽기 → 예제로 확인하기 → 이해 확인 → 종합 실습** 순서로 학습합니다. 강의에 따라 제공되는 예제와 활동이 다르며, 모든 강의에 실습이 붙어 있는 것은 아닙니다.

1. **본문에서 개념과 필요성을 이해합니다.** 도구 이름을 외우기보다 무엇을 해결하는지 먼저 확인합니다.
2. **그림과 활동으로 관계를 확인합니다.** 노드 예제가 있는 강의에서는 구성 요소를 연결하고 어떤 자료나 요청이 전달되는지 살펴봅니다.
3. **이해 확인 문제에 답합니다.** 정답 해설과 비교하고, 선택한 이유를 자기 말로 설명해 봅니다. 이해 확인만 있는 강의는 정답을 확인하면 완료가 기록됩니다.
4. **종합 실습에서 여러 개념을 연결합니다.** 실습이 있는 강의에서는 예시를 실행하고 잘못된 구성을 수정한 뒤, 화면에 제시된 목표를 달성합니다. 완료 조건에서 남은 목표를 확인할 수 있습니다.

사이트의 활동과 노드 실습은 관계를 이해하기 위한 **교육용 모형**입니다. 실제 AWS 자원을 만들거나 실제 모델을 학습하는 작업은 원문 자료의 명령과 설정을 따라 별도 환경에서 수행합니다. 심화 읽기와 비교 활동은 필요한 내용을 더 살펴보는 용도이며 필수 완료 조건은 아닙니다.

## 이 과정을 마치면

모델의 데이터·코드·실행 환경이 어디에서 관리되고, 학습 결과가 어떻게 서비스에 반영되는지 설명할 수 있는 것을 목표로 합니다. 문제가 생겼을 때 실행 환경, 저장소, 데이터 버전, 배포 상태, 운영 지표 중 어디부터 확인할지도 판단해 봅니다.

다음 강의에서는 **코드를 실행할 컴퓨터인 EC2**를, 이어서 **데이터와 모델 파일을 보관할 S3**를 배웁니다. 전체 과정의 출발점인 실행과 저장부터 구분해 보겠습니다.

<LessonSummary>

**MLOps는 머신러닝의 개발·배포·운영을 연결하고, 그 과정을 관리하며 반복할 수 있게 하는 실천입니다.**

- 버전과 실행 환경을 기록해 결과를 추적하고, 작업을 연결해 반복하며, 평가를 거쳐 배포하고 운영 상태를 관찰합니다.
- 이 과정은 0~9단원에 걸쳐 실행·저장 기초, 데이터와 학습 관리, 검색 응용, 서빙·배포·모니터링을 배운 뒤 전체 흐름을 종합합니다.
- 본문과 예제에서 개념을 익히고 이해 확인과 종합 실습으로 연결 관계를 확인합니다. 다음 학습은 EC2와 S3입니다.

</LessonSummary>
