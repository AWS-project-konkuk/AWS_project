## 문제 상황과 전체 맥락

GPU 두 장이면 모델 메모리도 절반일까요? 각 GPU가 다른 데이터를 처리하고 기울기를 동기화합니다.

## 개념 이해

데이터 병렬은 각 GPU에 같은 모델을 복제하고 서로 다른 데이터 묶음을 처리합니다. 각 복제본의 기울기를 모아 같은 모델 상태로 갱신합니다. 따라서 모델 학습 상태가 GPU 한 장에 들어가는 조건을 먼저 확인해야 합니다.

> **연결 전에 예측하기** — 각 GPU에는 전체 모델이 복제되어 있다고 가정합니다. 서로 다른 데이터로 구한 기울기를 모으는 흐름을 확인하세요.

<NodeExample />

연결을 따라가며 확인한 자료는 **기울기 g1 · 기울기 g2**입니다. 처리량을 높이는 목적과 모델을 여러 장치에 나눠 담는 목적을 구분합니다. 동기화 비용과 데이터 공급이 커지면 GPU를 추가해도 선형으로 빨라지지 않습니다.

## 관찰한 결과 해석하기

GPU 수가 늘어도 한 장당 모델 복제본 메모리는 없어지지 않습니다. 작업 분할로 연산 시간이 줄어도 기울기 통신이 새 병목이 될 수 있습니다. GPU 수와 통신 비용을 함께 바꾸고 선형 가속이 깨지는 지점을 관찰하세요.

## 적용 조건과 한계

혼합 정밀도가 전체 메모리를 항상 절반으로 줄이지는 않습니다. 일반 데이터 병렬은 전체 모델 상태를 GPU마다 복제합니다. 모델 상태를 나누는 전략과 통신 비용을 함께 비교해야 합니다.

## 전체 과정과 연결하기

데이터 병렬은 각 GPU에 같은 모델을 두고 다른 배치를 계산한 뒤 기울기를 동기화해 모델을 갱신합니다. 기본적인 복제 방식에서는 각 장치가 모델 학습 상태를 담을 수 있어야 합니다.
