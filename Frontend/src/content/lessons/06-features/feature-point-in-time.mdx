## 개념과 동작 원리

Point-in-Time Correctness는 학습 행의 예측 시점에 이용 가능했던 피처를 연결하는 기준입니다. 피처의 이벤트 시점뿐 아니라 도착 지연과 가용 시점도 고려해야 합니다. 정의 버전·집계 창·갱신 시점이 다르면 같은 피처 이름만으로 학습과 서빙의 일관성을 판단할 수 없습니다.

## 자료와 요청의 흐름

원천 이벤트 → 공통 피처 계산 → 과거 시점 학습 조회와 최신 온라인 조회로 분기합니다. Offline Store는 대량 과거 자료를, Online Store는 낮은 지연의 키 조회를 담당합니다. 배치 materialization이나 스트리밍 갱신의 주기는 요구 신선도에 맞추며 지연·누락을 관측합니다.

## 비교와 한계

Feature Store를 설치하는 것만으로 정의 불일치와 미래 정보 누출이 사라지지 않습니다. 과거 예측 시점에 실제로 알 수 있었던 값만 조인하고, 온라인 갱신의 지연·실패도 관측해야 합니다.

## 전체 과정과 연결

학습 때 최근 1시간 클릭 수를 사용했는데 서비스가 하루 클릭 수를 넣으면 같은 이름의 피처라도 의미가 달라집니다. 또한 요청마다 전체 로그를 집계하면 응답이 늦어집니다. 피처의 정의·시점·갱신 기준을 공유하고, 대량의 과거 조회와 낮은 지연의 현재 조회에 맞는 저장 경로를 나눠야 합니다.
