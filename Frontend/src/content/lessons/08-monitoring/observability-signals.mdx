## 개념과 동작 원리

Metrics는 지연·오류율 같은 집계 추세를, Logs는 사건의 상세 기록을, Traces는 서비스 사이의 요청 구간과 시간을 보여줍니다. Prometheus는 노출된 메트릭을 주기적으로 수집하고 시계열로 저장하며 규칙을 평가합니다. 로그와 트레이스를 자동으로 모두 수집하는 도구는 아닙니다.

## 자료와 요청의 흐름

알림 → 지표로 시점·영향 범위 확인 → 트레이스로 느린 구간 확인 → 관련 로그와 버전 조사 순서로 접근합니다. 모델 품질은 정답 표본이나 업무 지표를 별도로 수집해야 합니다. LLM 서비스에서는 성능·품질·비용·안전을 함께 보되 관측 자료와 평가 기준을 직접 설계해야 합니다.

## 비교와 한계

입력 분포 변화가 반드시 정확도 하락을 뜻하지는 않습니다. 정답이 늦게 오는 서비스에서는 품질 확인도 지연됩니다. 지표만으로 개별 요청의 원인을 알기 어려우므로 로그·트레이스와 함께 조사합니다.

## 전체 과정과 연결

HTTP 응답이 정상이어도 예측 품질은 떨어질 수 있습니다. 지연·오류율·자원 사용량은 시스템 상태를, 정답이 있는 표본의 정확도와 입력 분포는 모델 상태를 설명합니다. 알림은 조사할 신호이며 자동 재학습이나 자동 배포의 근거가 아닙니다. 수집 오류와 피처 변경도 먼저 확인해야 합니다.
