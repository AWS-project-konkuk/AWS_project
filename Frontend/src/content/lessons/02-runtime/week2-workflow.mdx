## 모델 파일에서 사용자 응답까지

팀원이 리뷰의 긍정·부정을 분류하는 모델을 사용하고 싶어 합니다. 모델 파일을 전달하는 것만으로는 리뷰를 입력하거나 예측을 받을 수 없습니다. 모델을 읽는 앱, 앱을 실행할 공간, 사용자 요청이 오가는 경로를 함께 준비해야 합니다.

| 화면의 항목                  | 실습에서 하는 일                                   |
| ---------------------------- | -------------------------------------------------- |
| EC2                          | Docker와 Kubernetes를 배치할 공간을 제공한다.      |
| Docker 영역의 이미지         | 서빙 앱과 실행 환경을 제공한다.                    |
| Kubernetes 영역의 Deployment | 사용할 이미지와 원하는 Pod 수를 지정한다.          |
| Kubernetes 영역의 Service    | 사용자 요청을 여러 경로로 나누어 전달한다.         |
| Pod                          | 서빙 앱이 모델과 이미지를 받아 예측 응답을 만든다. |

Deployment와 Service는 Kubernetes 영역 안에 있는 설정 노드입니다. Deployment에서 Pod로 보내는 선은 관리 선언을 나타냅니다. 사용자 요청은 Service에서 Pod로 전달됩니다.

## 두 Pod로 요청 10건 처리하기

1. **실습 시작하기**를 눌러 캔버스를 엽니다. 시스템 제목을 누르면 오른쪽 설정과 하단 도구 묶음이 바뀝니다.
2. 캔버스 상단에서 **전체 서비스**를 선택하고 **내부 일괄 실행**을 누릅니다. 시스템과 Pod·컨테이너는 개별로 실행 상태를 바꿀 수도 있습니다. Deployment·Service·모델 파일·이미지는 전체 실행에서 설정과 연결에 따라 자동으로 사용됩니다.
3. **출발 → Service** 요청 연결은 준비되어 있습니다. 아래 표를 따라 두 Pod의 입력과 출력을 연결합니다. 출력에서 입력으로 끌거나 두 포트를 차례로 클릭합니다.
4. **실습 실행**을 눌러 도착 노드에 응답 10건이 모이는지 확인합니다. 왼쪽 실행 결과의 **이해 확인**에 답하면 강의 완료가 기록됩니다.

| 출력            | 입력    | 전달 자료   |
| --------------- | ------- | ----------- |
| 컨테이너 이미지 | Pod 1·2 | 실행 이미지 |
| 모델 파일       | Pod 1·2 | 학습된 모델 |
| Deployment      | Pod 1·2 | 관리 선언   |
| Service         | Pod 1·2 | 리뷰 요청   |
| Pod 1·2         | 도착    | 예측 응답   |

연결과 이름을 새로 구성해도 같은 모델·이미지·Deployment를 쓰는 두 Pod가 요청을 나눠 정상 응답을 보내면 성공입니다. 이 실습의 예측과 요청 분배는 학습을 위한 모형입니다.

## 문제를 만들어 보고 복구하기

| 조작                                   | 관찰할 것                                                                        |
| -------------------------------------- | -------------------------------------------------------------------------------- |
| 모델에서 Pod로 가는 선을 우클릭해 삭제 | 어느 Pod에서 모델을 받지 못했고, 응답이 몇 건 도착했는지 확인한다.               |
| Deployment의 이미지 태그 변경          | 준비된 이미지와 선언한 이미지가 다르면 어느 노드에서 막히는지 확인한다.          |
| Kubernetes 정지                        | 내부 Pod의 실행 설정은 유지되지만, 해당 영역의 요청 처리와 관리 선언은 차단된다. |
| 도구 묶음에서 Pod 추가                 | Deployment가 관리할 Pod의 수와 요청이 전달되는 경로를 각각 확인한다.             |

삭제나 편집을 되돌리려면 **실행 취소**를 누릅니다. 시작할 때의 구성으로 돌아가려면 **초기 복원**을 누릅니다.

<LessonSummary>

모델 파일을 서비스로 제공하려면 실행 이미지와 요청 경로가 필요합니다. Pod의 앱이 모델을 읽어 예측하고, Deployment와 Service는 각각 실행본 관리와 요청 전달을 맡습니다.

</LessonSummary>
