## 서버를 빌렸는데, 왜 실행이 안 될까요?

0단원에서 EC2라는 컴퓨터를 빌리고, S3에 데이터와 모델을 보관하는 방법을 배웠습니다. 이제 리뷰를 긍정·부정으로 분류하는 프로그램을 EC2에서 실행하려고 합니다. 그런데 이런 말을 듣습니다.

> 어… 제 컴퓨터에서는 잘 되는데요?

컴퓨터까지 빌렸는데 프로그램이 낯을 가립니다. 코드는 같아도 Python 버전, 설치한 패키지, 파일 경로와 설정이 다르면 실행 결과가 달라질 수 있습니다. **이번 단원에서는 프로그램의 실행 환경을 묶어서 옮기고, 그 환경으로 서비스를 계속 실행하는 방법을 배웁니다.**

## 이번 단원에서 해결할 두 가지

첫째는 **무엇으로 실행할 것인가**입니다. 코드와 필요한 라이브러리를 이미지로 묶고, 그 이미지에서 컨테이너를 실행합니다. Docker가 이 과정을 도와줍니다.

둘째는 **실행한 서비스를 어떻게 유지할 것인가**입니다. 컨테이너가 여러 개가 되면 실행 위치, 개수, 장애 복구, 사용자 요청의 목적지를 관리해야 합니다. Kubernetes가 필요한 이유입니다. 사람 한 명이 서버 백 개를 보고 있다가 꺼질 때마다 켜는 방식은, 취업이 아니라 야간 당직에 가깝습니다.

| 이어지는 질문                                     | 이번에 배울 도구와 원리       |
| ------------------------------------------------- | ----------------------------- |
| 실행 환경을 분리하는 방법은 무엇일까?             | VM과 컨테이너                 |
| 프로그램과 의존성을 어떻게 묶고 실행할까?         | Docker와 Dockerfile           |
| 같은 커널을 쓰는데 어떻게 서로 구분할까?          | Namespaces와 Cgroups          |
| 묶어 둔 환경 하나로 여러 실행본을 만들 수 있을까? | 이미지와 컨테이너             |
| 실행본을 여러 서버에 배치하고 유지하려면?         | Kubernetes, Pod, Deployment   |
| 실행 중인데 왜 사용자 요청은 안 들어올까?         | 배치 경로와 Service 요청 경로 |

## 리뷰 분류 서비스를 끝까지 따라갑니다

이번 단원의 공통 사례는 **리뷰 분류 프로그램을 다른 컴퓨터에서도 실행하고, 장애 뒤에도 요청을 처리하게 만드는 일**입니다. 실제 모델 학습 방법은 이번 단원의 주제가 아닙니다. 이미 준비한 프로그램과 모델을 어떻게 실행할지에 집중합니다.

```text
코드 + 실행에 필요한 파일
          ↓ Dockerfile로 빌드
        실행 이미지
          ↓ 컨테이너 실행
        리뷰 분류 서버
          ↓ 여러 실행본이 필요해짐
 Kubernetes에서 Pod로 관리
          ↓ Service를 통한 요청 전달
        사용자가 응답을 받음
```

위 그림은 작업 순서입니다. 사용자 요청이 들어올 때마다 Dockerfile부터 다시 빌드한다는 뜻은 아닙니다. 음식 주문할 때마다 주방을 새로 짓지는 않잖아요. 준비 과정과 실제 요청 처리를 나누어 봅니다.

## 어떻게 확인하면 되나요?

설명을 읽은 뒤에는 **예상 → 조작 → 결과 확인 → 이유 설명** 순서로 진행합니다. 이미지 레슨에서는 같은 이미지를 두 컨테이너에 연결하고, 요청 경로 레슨에서는 관리 정보와 실제 요청의 화살표를 구분합니다. 마지막 실습에서는 버전 불일치와 장애 상황을 직접 수정합니다.

사이트의 노드와 활동은 교육용 모형입니다. 마지막 레슨에는 로컬 Docker와 Kubernetes에서 실행할 수 있는 추가 실습도 제공합니다. 실제 명령을 따라 하는 부분과 브라우저에서 구성 관계를 확인하는 부분은 구분해 안내합니다.

<LessonSummary>

이번 단원의 목표는 **같은 실행 환경을 준비하고, 그 환경으로 서비스를 유지하는 흐름**을 이해하는 것입니다. Docker는 이미지 제작과 컨테이너 실행을, Kubernetes는 여러 실행본의 배치와 원하는 상태 유지를 다룰 때 연결됩니다.

- EC2는 실행할 컴퓨터, 이미지는 실행 환경의 묶음, 컨테이너는 그 환경으로 만든 실행본입니다.
- 실행 환경 준비 → 실행본 관리 → 사용자 요청 전달을 구분합니다.
- 다음 레슨에서는 VM과 컨테이너가 무엇을 따로 갖고 무엇을 공유하는지 비교합니다.

</LessonSummary>
