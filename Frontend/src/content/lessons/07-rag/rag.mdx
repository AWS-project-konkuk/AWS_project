## 그럴듯한데 지난달 규정입니다

반품 기한이 바뀌어 도움말을 고쳤습니다. 그런데 챗봇은 새 문서가 올라온 뒤에도 옛 규정을 아주 자신 있게 안내합니다. 고객에게 필요한 건 자신감보다 최신 반품 정책입니다. 모델이 답을 쓰기 전에 관련 문서를 읽게 하려면 무엇을 연결해야 할까요?

## 개념 이해

**RAG**(Retrieval-Augmented Generation, 검색 증강 생성)는 LLM이 답하기 전에 믿을 수 있는 자료에서 관련 내용을 **검색**하고, 그 내용을 문맥으로 넣어 답을 **생성**하게 하는 구조입니다. LLM은 학습 시점 이후의 정보나 회사 내부 문서를 모르기 때문에, 그럴듯하지만 틀린 답(환각)을 만들 수 있습니다. RAG는 모델을 다시 학습시키지 않고 필요한 근거를 그때그때 전달해 이 문제를 줄입니다.

벡터 DB는 이 구조에서 **질문과 의미가 가까운 문서 조각을 빠르게 찾는** 역할을 합니다. 문서가 많아지면 모든 문서와 코사인 유사도를 계산하는 방식은 너무 느리므로, 앞에서 배운 HNSW 같은 ANN 인덱스로 top-k를 찾습니다. 검색 결과는 답의 근거일 뿐 최종 답변 자체는 아닙니다.

| ----------- | -------------------------------------------------- | ----------- |

| 검색        | 질문을 같은 모델로 임베딩해 가까운 청크 top-k 조회 | 요청 (매번) |
| 문맥 보강   | 검색한 청크를 질문과 함께 프롬프트에 넣음          | 요청 (매번) |
| 생성        | LLM이 근거를 바탕으로 답하고 출처를 밝힘           | 요청 (매번) |

> **연결 전에 예측하기** — 문서는 미리 색인됐다고 가정합니다. 질문 처리 단계에서 검색한 문서가 생성 입력으로 들어가는 부분을 연결하세요.

연결을 따라가며 확인한 자료는 **질문 벡터 · 문서 색인 · 검색한 문서 근거**입니다. 검색된 문서의 관련성·최신성부터 확인하고 답변의 근거 사용을 검토합니다. 검색 오류와 생성 오류를 구분해야 어느 단계를 고칠지 정할 수 있습니다.

프롬프트 조립은 보통 다음과 같은 모양입니다.

```text
다음 근거만 사용해 질문에 답하세요. 근거에 없는 내용이면 "문서에서 찾을 수 없습니다"라고 답하세요.

[근거 1] (반품정책.pdf, 2026-10) 상품 수령 후 14일 이내에 반품을 신청할 수 있습니다. ...
[근거 2] (FAQ, 2026-09) 단순 변심 반품은 왕복 배송비가 부과됩니다. ...

질문: 반품 기한이 어떻게 되나요?
```

## 관찰한 결과 해석하기

근거가 없을 때, 관련 근거를 전달했을 때, 관련 없는 근거를 전달했을 때의 답변을 비교하세요.

<Activity />

검색이 틀리거나 근거가 오래되면 답변도 잘못될 수 있습니다. RAG는 환각을 줄이는 데 도움을 주지만 제거를 보장하지 않습니다. 여기서는 고정된 문서와 응답을 사용해 근거 전달의 차이를 확인합니다.

## 적용 조건과 한계

**RAG의 장점**

- **최신 정보 반영**: 문서를 벡터 DB에 추가·갱신하면 모델을 다시 학습하지 않아도 답에 반영됩니다.
- **비용 절감**: 파인튜닝 없이 도메인 지식을 활용할 수 있습니다.
- **내부 데이터 활용**: 회사 내부 문서를 모델 학습에 넣지 않고 검색 대상으로만 둘 수 있습니다. 다만 사용자 권한에 맞는 문서만 검색되도록 메타데이터 필터를 함께 설계해야 합니다.
- **설명 가능성**: 어떤 문서를 근거로 답했는지 출처를 함께 보여 줄 수 있습니다.

**RAG의 한계**

- **검색 실패**: 관련 문서가 없거나 top-k 밖에 있으면, 모델이 근거 없이 답을 지어낼 수 있습니다. 근거가 없을 때 답을 보류하도록 지시하고 평가해야 합니다.
- **Garbage in, garbage out**: 오래되었거나 서로 모순되는 문서가 검색되면 답도 틀립니다.
- **청킹의 균형**: 청크가 너무 작으면 문맥이 잘리고, 너무 크면 관련 없는 내용이 섞여 검색 정확도가 떨어집니다.
- **임베딩 품질**: 임베딩 모델이 질문과 문서의 의미를 잘 구분하지 못하면 검색부터 틀립니다.
- **컨텍스트 창 제한**: 근거를 너무 많이 넣으면 토큰 한도를 넘거나, 중요한 근거가 묻혀 답의 품질이 떨어집니다.

## 전체 과정과 연결하기

문서를 분할·임베딩해 색인하는 준비 경로와, 질문을 임베딩해 관련 문서를 검색하고 생성에 전달하는 요청 경로가 있습니다. 색인 경로는 문서가 바뀔 때마다 다시 실행되어야 하므로, MLOps 관점에서는 문서 수집·임베딩 파이프라인의 버전과 갱신 주기도 함께 관리합니다.

<Callout title="판단할 때 확인하기">

검색된 문서의 관련성·최신성부터 확인하고 답변의 근거 사용을 검토합니다. 검색 품질(recall@k)과 생성 품질(근거 충실도)을 따로 평가합니다.

</Callout>

<LessonSummary>

RAG는 LLM이 답하기 전에 벡터 DB에서 질문과 의미가 가까운 문서 조각을 검색하고, 그 근거를 프롬프트에 넣어 답을 생성하게 하는 구조입니다. 문서를 청킹·임베딩해 색인하는 준비 경로와, 질문을 같은 모델로 임베딩해 top-k를 검색하고 생성에 전달하는 요청 경로로 나뉩니다. 재학습 없이 최신·내부 정보를 반영하고 출처를 보여 줄 수 있지만, 환각 제거를 보장하지는 않습니다.
