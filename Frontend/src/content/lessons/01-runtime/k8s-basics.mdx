## 개념 이해

Kubernetes는 컨테이너를 Pod 단위로 배치하고 실행 상태를 관리합니다. Deployment에 원하는 복제본 수를 선언하면 컨트롤러가 실제 상태를 그 수에 가깝게 유지합니다. Service는 바뀌는 Pod 집합에 접근할 안정적인 경로를 제공합니다.

클러스터 접근 권한이 있는 환경에서 선언과 실행 상태를 비교할 때 사용하는 조회 예제입니다.

```bash
kubectl get deployments
kubectl get pods
kubectl get services
```

Deployment의 원하는 복제본과 실제 Pod 상태를 비교한 뒤 Service의 경로를 확인합니다. 조회 결과만으로 모든 요청의 성공을 확정할 수는 없으므로 준비 상태와 실제 응답도 점검합니다.

## 관찰한 결과 해석하기

복제본 복구와 부하에 따른 자동 확장은 다른 기능입니다. 여기서는 Pod·Deployment·Service의 역할만 배우며 스케줄러·네트워크 구축 등 세부 운영은 다루지 않습니다. Kubernetes는 MLOps를 위한 필수 조건이 아닙니다.

## 적용 조건과 한계

컨테이너는 호스트 커널을 공유합니다. 이미지가 같아도 GPU 드라이버나 외부 설정이 다를 수 있습니다. Deployment의 복제본 유지와 HPA의 부하 기반 확장은 별도 기능입니다.

## 전체 과정과 연결하기

Deployment에 원하는 복제본 수를 선언하면 컨트롤러는 부족한 Pod를 다시 생성합니다. Service는 선택 조건에 맞는 준비된 Pod로 요청을 전달하는 안정적인 진입점을 제공합니다.
