그림의 **`Dockerfile`**, **이미지**, **실행 컨테이너**에 주목해 보세요. Dockerfile과 빌드 문맥으로 이미지를 만들고, 그 이미지로 컨테이너를 생성해 실행합니다.

## 개념 이해

docker build는 빌드 문맥과 Dockerfile로 이미지를 만듭니다. docker images는 이미지 목록을 확인하고 run은 컨테이너를 생성·시작합니다. ps와 logs는 상태와 출력을 관찰하는 명령입니다.

실행 환경이 준비된 셸에서 확인하는 명령 예제입니다. 컨테이너 ID는 실제 값으로 바꿔야 합니다.

```bash
docker images
docker ps -a
docker logs <컨테이너-ID>
```

첫 명령은 보관한 이미지를, 두 번째는 생성된 컨테이너의 상태를, 마지막은 지정한 컨테이너의 출력을 보여줍니다. 목록 조회 자체는 실행 상태를 바꾸지 않습니다.

## 관찰한 결과 해석하기

stop은 실행을 멈추지만 컨테이너를 삭제하지 않습니다. rm은 멈춘 컨테이너를 제거합니다. 이 활동은 실제 셸이 아닌 제한된 상태 실험이므로 호스트에 Docker를 설치하거나 명령을 실행하지 않습니다.

## 적용 조건과 한계

컨테이너는 호스트 커널을 공유합니다. 이미지가 같아도 GPU 드라이버나 외부 설정이 다를 수 있습니다. Deployment의 복제본 유지와 HPA의 부하 기반 확장은 별도 기능입니다.

## 전체 과정과 연결하기

Dockerfile과 빌드 문맥으로 이미지를 만들고, 그 이미지로 컨테이너를 생성해 실행합니다. 이미지 목록, 실행 목록, 로그를 차례로 확인하면 준비한 환경과 실제 실행을 연결할 수 있습니다.
