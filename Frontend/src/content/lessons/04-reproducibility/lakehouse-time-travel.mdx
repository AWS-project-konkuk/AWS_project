## 문제 상황

S3에 CSV, JSON, 이미지와 Parquet 파일을 대량으로 저장했지만 어떤 파일이 현재 테이블에 속하는지, 특정 시점에는 어떤 파일이 유효했는지 알기 어렵습니다. Data Lakehouse는 객체 저장소의 확장성과 테이블 메타데이터의 관리 기능을 결합합니다.

## 개념과 동작 원리

### Data Warehouse, Data Lake, Data Lakehouse

| 구분           | 강점                                         | 주의할 점                                 |
| -------------- | -------------------------------------------- | ----------------------------------------- |
| Data Warehouse | 정제된 정형 데이터를 SQL로 분석              | 반정형·비정형 데이터 적재 전 변환 비용    |
| Data Lake      | 다양한 원본 데이터를 대량 보관               | 관리가 약하면 파일을 찾고 신뢰하기 어려움 |
| Data Lakehouse | 객체 저장소에 테이블·버전·트랜잭션 관리 추가 | 포맷·카탈로그·엔진 운영 필요              |

일반적인 레이크하우스는 실제 파일을 두는 Storage Layer, 유효한 파일과 스냅샷을 관리하는 Table Format Layer, 필요한 파일을 읽어 계산하는 Compute Layer로 이해할 수 있습니다.

### 오픈 테이블 포맷

Apache Iceberg와 Delta Lake 같은 오픈 테이블 포맷은 객체 저장소의 여러 데이터 파일을 논리적 테이블로 관리합니다. 파일 경로 목록을 애플리케이션이 직접 조합하는 대신 메타데이터가 현재 테이블 상태를 설명합니다.

```text
Iceberg Catalog
  → Table Metadata
    → Snapshot
      → Manifest List
        → Manifest
          → 필요한 Parquet 데이터 파일
```

Delta Lake는 트랜잭션 로그와 체크포인트를 이용해 테이블 상태를 구성합니다. 내부 구조는 다르지만 새 데이터 파일을 먼저 쓰고 메타데이터나 로그 커밋으로 새 테이블 버전을 확정한다는 공통된 관점이 있습니다.

### 객체 저장소 위의 ACID

기존 파일 'A, B'에서 'B'의 데이터를 수정할 때 파일을 직접 덮어쓰기보다 새 파일 'C'를 만들고 새 메타데이터가 'A, C'를 가리키도록 준비합니다. 마지막 커밋이 성공해야 새 버전 전체가 보입니다.

- Atomicity: 이전 버전 전체 또는 새 버전 전체가 보이도록 커밋합니다.
- Consistency: 스키마와 테이블 규칙을 검증합니다.
- Isolation: 스냅샷과 충돌 검사를 통해 동시 변경을 제어합니다.
- Durability: 커밋된 데이터와 메타데이터를 영속 저장소에 보관합니다.

두 작성자가 같은 기준 버전에서 동시에 수정하면 먼저 성공한 커밋 뒤 다른 작성자의 조건부 갱신은 충돌할 수 있습니다. 이때 재검증·재시도하거나 실패 처리하는 낙관적 동시성 제어를 사용할 수 있습니다.

### Time Travel과 Schema Evolution

Time Travel은 과거 스냅샷을 조회하는 기능입니다. 과거 모델이 읽었던 데이터 상태를 확인하거나 오염 전 데이터를 분석하는 데 유용합니다. 과거 조회와 현재 상태를 과거로 되돌리는 rollback은 구분해야 합니다.

Schema Evolution은 컬럼 추가·이름 변경 같은 구조 변화를 메타데이터로 관리합니다. 모든 과거 파일을 즉시 다시 쓰지 않고도 스키마를 발전시킬 수 있지만 변경 종류와 엔진 지원 범위를 확인해야 합니다.

## 비교와 한계

DVC는 파일·디렉터리 버전을 코드와 연결하고 ML 파이프라인 재현을 돕습니다. 레이크하우스는 많은 사용자가 공유하는 테이블의 스냅샷·트랜잭션·스키마를 관리합니다. 둘은 관리 대상과 사용 규모가 다릅니다.

- Time Travel은 과거 시점을 조회하는 기능이며 현재 테이블을 자동으로 되돌리는 기능은 아닙니다.
- 스냅샷을 오래 보존하려면 메타데이터와 참조 데이터 파일의 보존 정책을 함께 설계해야 합니다.
- 테이블 포맷을 선택할 때 카탈로그와 처리 엔진의 호환성을 확인해야 합니다.

## 전체 과정과 연결

DVC가 개별 실험의 파일 버전과 실행 단계를 연결한다면 레이크하우스는 여러 작업이 공유하는 테이블 상태와 시점을 관리합니다. 두 방식을 목적에 맞게 사용하면 과거 실험 입력을 더 정확하게 찾을 수 있습니다.

<LessonSummary>

Data Lakehouse는 객체 저장소의 확장성 위에 오픈 테이블 포맷의 메타데이터 관리를 더합니다. Iceberg는 메타데이터·스냅샷·Manifest로, Delta Lake는 트랜잭션 로그와 체크포인트로 유효한 파일 집합을 설명합니다. 새 파일을 먼저 만들고 새 버전을 원자적으로 커밋하여 ACID와 동시성 제어를 제공하며, Time Travel과 Schema Evolution은 과거 데이터 재현과 안전한 구조 변경을 돕습니다.
