## 문제 상황

과거 실험을 다시 실행하려면 Git 커밋만 되돌려서는 부족합니다. 코드와 DVC 포인터, 실제 데이터, 파라미터와 실행 환경이 함께 맞아야 합니다. 이번 노드 실습에서는 Git 메타데이터와 DVC 캐시·원격의 역할을 연결해 v1 실험을 복원합니다.

## 개념과 동작 원리

### 이번 미션

Git은 v1 코드와 'dataset.dvc'를 선택했지만 작업 공간의 실제 데이터는 v2입니다. 로컬 캐시에는 v1 객체가 없습니다. 노드를 올바르게 연결하고 원격에서 v1을 가져와 코드와 데이터가 일치하는 작업 공간을 만드세요.

### 노드 역할

| 노드           | 담당하는 것                               |
| -------------- | ----------------------------------------- |
| Git 커밋       | 코드와 데이터 포인터 버전 선택            |
| DVC 원격       | 팀이 공유하는 실제 v1·v2 데이터 객체 보관 |
| 로컬 캐시      | 내용 식별자로 데이터를 찾고 재사용        |
| 작업 공간 복원 | 코드와 실제 데이터를 실행 경로에 배치     |
| 실험 재현 확인 | 입력 버전을 검증하고 모델 생성            |

### 실습 순서

1. **2. 잘못된 구성 수정**을 불러오고 연결 검사로 빠진 자료를 확인합니다.
2. Git 커밋의 코드·포인터를 작업 공간 복원에 연결합니다.
3. DVC 원격의 실제 데이터를 로컬 캐시에 연결하고 캐시를 작업 공간 복원에 연결합니다.
4. 작업 공간 스냅샷을 실험 재현 확인 노드로 전달합니다.
5. 복원 작업을 **Git 이동만**으로 두고 코드 v1과 데이터 v2의 불일치를 관찰합니다.
6. **dvc checkout**을 선택해 캐시에 v1이 없을 때의 실패를 확인합니다.
7. **dvc pull 후 복원**으로 바꾸고 v1 코드·데이터가 함께 복원되는지 확인합니다.

### 결과 해석

Git 이동만으로는 실제 데이터가 과거로 돌아오지 않습니다. 'dvc checkout'은 필요한 객체가 로컬 캐시에 있을 때 사용할 수 있고, 없으면 'dvc pull'로 원격에서 가져와야 합니다. 성공 출력의 작업 공간이 '코드 v1 + 실제 데이터 v1'인지 확인하세요.

이 실습은 DVC 복원 경로를 단순화한 모형입니다. 실제 재현에는 'params.yaml', 'dvc.yaml', 패키지와 컨테이너 이미지, 난수 설정도 함께 기록해야 합니다.

## 비교와 한계

- Git 이동만으로는 작업 공간의 실제 데이터가 과거 버전으로 바뀌지 않습니다.
- 로컬 캐시에 데이터가 없으면 데이터 원격에서 가져와야 합니다.
- 성공한 모의 실행은 패키지·난수·하드웨어까지 완전히 같은 환경을 보장하지 않습니다.

## 전체 과정과 연결

Git에서 코드와 포인터를 선택하고 DVC 캐시·원격에서 실제 데이터를 복원한 뒤, 파라미터와 실행 환경까지 확인하면 과거 실험을 같은 입력 조건으로 다시 실행할 수 있습니다.

<LessonSummary>

과거 실험 복원은 Git에서 코드와 DVC 포인터를 선택하는 단계와 포인터가 가리키는 실제 데이터를 복원하는 단계로 나뉩니다. 로컬 캐시에 데이터가 있으면 'dvc checkout'으로 작업 공간을 구성할 수 있고, 없다면 'dvc pull'로 데이터 원격에서 가져와야 합니다. 마지막에는 코드·데이터·파라미터·환경이 같은 버전인지 검증해야 재현 결과를 신뢰할 수 있습니다.

</LessonSummary>
