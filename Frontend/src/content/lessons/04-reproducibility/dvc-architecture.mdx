## 코드는 왔는데 고양이가 없습니다

팀원이 Git에서 학습 코드를 받고 실행했더니 첫 줄부터 사진 폴더를 찾을 수 없다고 나옵니다. 고양이 분류 프로젝트에서 고양이만 빠졌습니다. 코드가 요구하는 정확한 데이터 버전을 팀원이 어떻게 다시 가져올 수 있을까요?

**DVC(Data Version Control)**는 Git과 함께 사용하면서 어떤 버전의 데이터를 썼는지 기록하고, 필요한 실제 파일을 다시 찾도록 돕는 도구입니다. 그림에서 버전 기록과 실제 데이터가 어디에 있는지 각각 따라가 보세요.

## 네 장소만 구분하면 됩니다

| 이름        | 쉽게 말하면        | 담고 있는 것               |
| ----------- | ------------------ | -------------------------- |
| Git         | 실험 기록장        | 코드와 데이터 이름표       |
| 작업 공간   | 지금 쓰는 폴더     | 학습 코드가 읽는 실제 파일 |
| 로컬 캐시   | 내 컴퓨터의 보관함 | 다시 꺼내 쓸 데이터 내용   |
| 데이터 원격 | 팀의 공용 보관함   | S3 등에 공유한 실제 데이터 |

<strong>캐시(cache)</strong>는 나중에 재사용하려고 보관한 내용입니다. 내 보관함에 파일이 있으면 팀
보관함에서 매번 다시 받을 필요가 없습니다.

## .dvc 파일은 데이터의 이름표입니다

`.dvc`에는 파일 경로, 크기, **해시(hash)** 등이 들어갑니다. 해시는 파일 내용을 구분하는 지문 같은 값입니다. 이름이 같아도 내용이 달라졌는지 확인하는 데 사용합니다.

<details>
<summary>.dvc 파일 예시 보기</summary>

아래 해시는 설명용 값입니다. 실제 파일을 DVC로 추적하면 그 내용에 맞는 값이 기록됩니다.

```yaml
outs:
  - md5: 0123456789abcdef0123456789abcdef
    size: 10737418240
    path: data.zip
```

`path`는 이 `.dvc` 파일을 기준으로 한 데이터 경로이고, `size`는 바이트 단위 크기입니다. 예시의 `md5`는 내용을 구분하는 해시입니다. 여기서는 이름표와 데이터가 같은 폴더에 있으므로 `data.zip`이라고 적습니다. 해시만으로 실제 파일을 만들어 낼 수는 없습니다.

## 팀원과 공유할 때 확인할 것

코드와 이름표는 `git push`로 공유합니다. 실제 데이터는 `dvc push`로 공유합니다. 팀원은 Git 기록을 받은 뒤 `dvc pull`로 필요한 데이터를 준비합니다.

DVC가 관리하는 큰 데이터는 보통 `.gitignore`로 Git 추적에서 제외합니다. 이름표와 실제 파일을 같은 저장소에 올려야 한다고 생각하지 않아도 됩니다.

## 데이터 한 개를 등록하는 순서

`data.zip`을 공유할 데이터라고 가정합니다. DVC가 설치되어 있고 아직 DVC를 시작하지 않은 Git 프로젝트에서 다음 순서로 등록할 수 있습니다.

```bash
dvc init
dvc add data.zip
git add .dvc .dvcignore data.zip.dvc .gitignore
git commit -m "Track training dataset"
```

`dvc add`는 파일 내용에 맞는 캐시를 준비하고 데이터 이름표인 `data.zip.dvc`를 만듭니다. 데이터 파일 자체는 일반적으로 Git 추적에서 제외되도록 `.gitignore`에 기록합니다. Git에 추가하는 것은 큰 데이터 대신 **DVC 설정과 작은 이름표**입니다.

이 명령만으로 S3 업로드가 끝나지는 않습니다. 어떤 데이터 원격을 쓸지 설정하고, 접근 권한을 준비한 뒤 `dvc push`로 공유해야 합니다.

## 두 원격 저장소의 역할

```text
코드·data.zip.dvc ── git push ──▶ GitHub / GitLab
실제 데이터 캐시 ── dvc push ──▶ S3 / MinIO

팀원의 Git 기록: 필요한 데이터 내용을 확인
팀원의 캐시: 없으면 데이터 원격에서 받기
팀원의 작업 폴더: 확보한 파일을 꺼내 사용
```

Git으로 `.dvc`를 받았다고 S3에서 파일이 저절로 전달되지는 않습니다. 이름표를 읽고 필요한 내용을 캐시나 원격에서 확보하는 DVC 작업이 뒤따릅니다.

| 공유 대상                   | 보낼 곳                     | 사용하는 명령 |
| --------------------------- | --------------------------- | ------------- |
| 소스 코드와 데이터 이름표   | GitHub·GitLab 같은 Git 원격 | `git push`    |
| 이름표가 가리키는 실제 내용 | S3·MinIO 같은 데이터 원격   | `dvc push`    |

예를 들어 팀원이 Git 저장소만 받으면 “어떤 파일이 필요한지”는 알 수 있습니다. 그러나 그 파일이 아직 데이터 원격에 공유되지 않았다면 `dvc pull`도 데이터를 가져올 수 없습니다. 공유한 사람이 **Git 기록과 데이터 업로드를 모두 완료했는지** 확인해야 합니다.

민감한 접근 키는 코드나 이름표에 넣지 않습니다. 데이터 원격을 사용할 인증 정보와 권한은 실행 환경에서 별도로 준비합니다.

## 내용이 같으면 캐시를 다시 쓸 수 있습니다

내가 v1 데이터를 쓴 뒤 v2로 옮겼다가 다시 v1을 선택한다고 생각해 보세요. v1 내용이 로컬 캐시에 남아 있으면 그 내용을 작업 폴더에 다시 반영할 수 있습니다. 이미 보관한 물건을 꺼내 쓰는 것과 같습니다.

반대로 새 컴퓨터에는 캐시가 없을 수 있습니다. 이때는 데이터 원격에서 필요한 객체를 받아 캐시를 채우고 작업 폴더에 반영합니다. 캐시가 빠른 재사용을 돕는다면, 팀의 원격은 여러 컴퓨터가 파일을 확보할 수 있는 공유 경로입니다.

캐시는 모든 파일의 바뀐 바이트만 저장하는 방식이라고 이해하면 안 됩니다. 변경된 파일의 내용에 따라 새로운 객체가 필요할 수 있으며, 실제 저장량은 파일 구성과 변경 방식에 영향을 받습니다.

## .gitignore와 .dvcignore를 구분하세요

두 이름이 비슷하지만 사용하는 도구가 다릅니다.

- `.gitignore`는 Git에서 추적하지 않을 경로를 정합니다. 큰 데이터를 Git 이력에 중복해서 넣지 않는 데 사용합니다.
- `.dvcignore`는 DVC가 경로를 살펴볼 때 제외할 대상을 정합니다. 데이터 파일을 Git에서 제외하는 역할과는 다릅니다.

이미 Git으로 추적하던 파일은 `.gitignore`에 쓰는 것만으로 추적이 중단되지 않습니다. 기존 프로젝트의 추적 방식을 옮길 때는 어떤 도구가 어떤 파일을 관리하는지 먼저 확인해야 합니다.

<LessonSummary>

DVC는 데이터 내용을 구분하는 해시를 이름표에 기록하고, 실제 내용은 로컬 캐시와 데이터 원격에서 찾습니다. Git은 코드와 작은 메타데이터를, 캐시와 원격은 큰 데이터 내용을 담당합니다. git push와 dvc push는 공유하는 대상이 다릅니다. 팀원이 같은 데이터를 준비하려면 올바른 이름표와 그 이름표가 가리키는 실제 내용이 모두 필요합니다.

</LessonSummary>
