## 1GB짜리 모델이 왜 몇 줄밖에 안 될까요?

분명 1GB짜리 모델을 올렸는데 팀원이 받은 `model.pt`를 열어 보니 짧은 텍스트 몇 줄뿐입니다. 이름은 모델 파일인데, 내용은 영수증에 가깝습니다. 이 파일에는 무엇이 들어 있고, 실제 모델은 어디서 받아야 할까요? 답은 파일을 가리키는 포인터와 실제 내용을 따로 관리하는 Git LFS에 있습니다.

포인터에는 실제 파일을 식별할 정보가 들어 있습니다. 팀원은 Git에서 포인터를 받고, LFS 저장소에서 포인터가 가리키는 파일을 가져옵니다.

## 포인터는 파일을 찾는 이름표입니다

여기서 이름표의 정식 이름이 <strong>포인터(pointer)</strong>입니다. 포인터에는 어떤 내용의 파일인지와 파일 크기 등이 적혀 있습니다.

| 위치         | 보관하는 것                 |
| ------------ | --------------------------- |
| Git 저장소   | 코드와 작은 포인터          |
| LFS 저장소   | 실제 모델 파일              |
| 내 작업 폴더 | 내려받아서 사용할 모델 파일 |

팀원이 포인터가 가리키는 파일을 받아야 학습이나 예측에 사용할 수 있습니다. 파일을 받지 못했다면 저장소 권한과 다운로드 상태를 확인합니다.

## DVC와는 무엇이 다를까요?

Git LFS는 **큰 파일을 Git과 함께 관리하는 것**에 초점을 둡니다. 다음 수업의 DVC는 데이터 버전뿐 아니라 “자료 준비 → 학습 → 평가” 중 어느 부분을 다시 실행할지도 다룹니다.

두 도구 모두 실제 파일을 보관할 공간이 필요합니다. 포인터가 작다고 데이터 저장 용량까지 없어지는 것은 아닙니다.

## 파일이 오가는 순서를 따라가 봅시다

개발자 민수가 `model.pt`를 LFS로 관리하고 팀원 지수가 받는다고 가정합니다.

1. 민수의 작업 폴더에는 실제 `model.pt` 파일이 있습니다.
2. LFS가 적용된 파일을 Git에 추가하면 Git 기록에는 작은 포인터가 들어갑니다.
3. 공유 과정에서 실제 파일은 LFS 저장소에 올라갑니다.
4. 지수는 Git 기록을 받은 뒤 포인터에 맞는 실제 파일을 내려받습니다.
5. 지수의 프로그램은 작업 폴더의 실제 모델을 읽습니다.

여기서 Git 원격과 LFS 저장소는 같은 서비스에서 제공할 수도 있지만 **보관하는 내용의 역할은 다릅니다.** 코드 다운로드가 끝났어도 모델 다운로드는 실패할 수 있습니다.

## 어떤 파일에 LFS를 적용할까요?

LFS는 추적할 파일 규칙을 `.gitattributes`에 기록합니다. 예를 들어 모델 파일 확장자 `.pt`를 규칙에 넣으면 이후 해당 파일을 Git에 추가할 때 LFS 처리가 적용됩니다.

```bash
# Git LFS가 설치된 프로젝트에서 사용하는 예시
git lfs install
git lfs track "*.pt"
git add .gitattributes model.pt
git commit -m "Track model with Git LFS"
git push
```

실습용 모델 파일과 LFS를 지원하는 원격 저장소가 준비되어 있다고 가정한 명령입니다. 이 페이지의 선택 활동에서 실제 업로드를 수행하지는 않습니다.

`.gitattributes`도 함께 커밋해야 팀원이 같은 규칙을 받을 수 있습니다. 이미 과거 커밋에 일반 Git 파일로 넣은 내용까지 위 명령만으로 자동 정리되는 것은 아닙니다.

## 포인터의 작은 크기가 뜻하는 것

포인터는 파일을 찾기 위한 식별 정보이므로 실제 모델보다 훨씬 작습니다. 하지만 포인터를 작게 만든 만큼 모델 자체가 압축되어 사라지는 것은 아닙니다.

| 확인할 항목                           | 이유                                     |
| ------------------------------------- | ---------------------------------------- |
| Git 기록에 포인터가 있는가?           | 어떤 파일 버전인지 찾아야 함             |
| LFS 저장소에 그 파일이 있는가?        | 실제 내용을 받아야 함                    |
| 팀원에게 읽기 권한이 있는가?          | 파일이 있어도 권한이 없으면 받을 수 없음 |
| 작업 폴더에 실제 파일이 준비되었는가? | 모델을 실행하는 프로그램이 읽어야 함     |

<Callout title="다음 수업으로 이어지는 질문">

파일을 받는 것뿐 아니라, 이 데이터로 어떤 전처리와 학습을 했는지도 기록하려면 무엇이 더 필요할까요? DVC에서는 데이터 관리와 작업 순서를 함께 살펴봅니다.

</Callout>

<LessonSummary>

Git LFS는 Git 기록에는 작은 포인터를 두고 실제 큰 파일은 LFS 저장소에 보관합니다. 포인터는 파일을 찾는 정보이므로 파일의 저장 용량을 없애거나 내용을 대신하지 않습니다. 팀원이 같은 모델을 사용하려면 Git 기록과 실제 LFS 파일을 모두 받아야 합니다. 공유할 때는 추적 규칙, 실제 업로드 상태와 접근 권한까지 확인합니다.

</LessonSummary>
