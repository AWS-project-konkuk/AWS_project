## 문제 상황

Git을 과거 커밋 v1으로 이동했지만 작업 공간에는 데이터 v2가 남아 있습니다. Git은 코드와 '.dvc' 포인터를 바꿨을 뿐 실제 대용량 파일 내용을 자동으로 과거 버전으로 바꾸지 않습니다.

## 개념과 동작 원리

### 복원은 두 단계입니다

1. Git으로 코드와 '.dvc' 메타데이터의 버전을 선택합니다.
2. DVC가 포인터의 내용 식별자에 맞는 실제 데이터를 작업 공간에 복원합니다.

### 'checkout'과 'pull'의 차이

```bash
git switch <과거-커밋>
dvc checkout
```

'dvc checkout'은 현재 메타데이터에 맞는 내용을 로컬 캐시에서 작업 공간으로 구성합니다. 필요한 데이터가 캐시에 없다면 복원할 수 없습니다.

```bash
git switch <과거-커밋>
dvc pull
```

'dvc pull'은 필요한 객체를 데이터 원격에서 로컬 캐시로 가져오고 작업 공간을 맞춥니다. 원격에 객체가 없거나 접근 권한이 없으면 실패합니다.

### 복원 후 확인할 것

- 코드 커밋과 '.dvc' 파일이 의도한 버전인가?
- 작업 파일의 내용 해시가 포인터와 일치하는가?
- 'params.yaml'과 실행 환경도 같은가?
- 캐시에 없던 데이터가 원격에서 정상적으로 내려왔는가?

과거 데이터를 복원했다고 과거 실험이 완전히 재현되는 것은 아닙니다. 패키지·컨테이너·난수·하드웨어 조건도 결과에 영향을 줄 수 있습니다.

## 비교와 한계

- 'dvc checkout'은 로컬 캐시에 필요한 데이터가 있어야 합니다.
- 'dvc pull'은 데이터 원격의 객체와 접근 권한이 필요합니다.
- 데이터 복원만으로 패키지와 하드웨어까지 같은 실험 환경이 만들어지지는 않습니다.

## 전체 과정과 연결

Git에서 코드와 포인터를 선택하고 DVC로 실제 파일을 복원하면 코드·데이터 버전을 맞출 수 있습니다. 이후 파라미터와 실행 환경도 같은지 확인해야 과거 실험을 다시 실행할 수 있습니다.

<LessonSummary>

Git으로 과거 커밋을 선택하면 코드와 DVC 포인터가 바뀌지만 실제 데이터 파일은 자동으로 바뀌지 않습니다. 'dvc checkout'은 로컬 캐시에 있는 데이터를 작업 공간으로 복원하고, 캐시에 필요한 객체가 없을 때는 'dvc pull'로 데이터 원격에서 가져와야 합니다. 복원 뒤에는 코드·포인터·실제 데이터·파라미터·실행 환경의 버전이 함께 맞는지 확인해야 합니다.

</LessonSummary>
