## 지난주 코드로 돌아왔는데 점수는 왜 달라졌을까요?

지난주 모델이 더 잘 맞혀 Git에서 지난주 커밋을 꺼내 다시 돌렸습니다. 그런데 성적표가 다릅니다. 코드는 시간 여행에 성공했는데, 작업 폴더의 사진도 함께 따라왔을까요?

이번 수업에서는 **v1은 지난주 버전, v2는 이번 주 버전**이라고 부르겠습니다. 그림의 시작은 Git 기록이고, 도착점은 코드가 읽을 작업 파일입니다. 기록이 지난주 상태라도 도착점의 파일을 확인하기 전에는 복원이 끝났다고 판단할 수 없습니다.

## 기록과 실제 파일을 함께 맞춥니다

Git에서 v1을 선택하면 코드와 데이터 이름표가 지난주 상태로 돌아갑니다. 하지만 Git이 관리하지 않는 큰 데이터 파일은 별도로 복원해야 합니다.

| v1 데이터가 있는 곳 | 할 일                            | 명령                   |
| ------------------- | -------------------------------- | ---------------------- |
| 내 캐시             | 보관한 파일을 작업 폴더에 꺼내기 | `dvc checkout`         |
| 팀의 데이터 원격    | 내려받고 작업 폴더에 꺼내기      | `dvc pull`             |
| 두 곳 모두 없음     | 보존된 사본이나 백업 찾기        | 이름표만으로 복원 불가 |

`dvc pull`은 파일을 가져오는 일과 작업 폴더에 반영하는 일을 함께 합니다.

## 데이터 복원 다음에는 환경을 확인합니다

같은 데이터를 받았어도 학습 횟수나 라이브러리 버전이 다르면 결과가 달라질 수 있습니다. 코드·데이터를 맞춘 뒤에는 설정과 실행 환경도 확인합니다.

## v1과 v2가 섞이면 어떤 일이 생길까요?

지난주에는 사진 1,000장으로 모델을 학습했습니다. 이번 주에는 사진 200장을 추가하고 일부 정답도 고쳤습니다. 코드만 지난주로 돌아가더라도 1,200장을 읽으면 입력 조건이 달라집니다.

| 확인 시점           | 코드·이름표 | 작업 폴더 데이터 | 판단                           |
| ------------------- | ----------- | ---------------- | ------------------------------ |
| 이번 주 실험        | v2          | v2               | 이번 주 조건                   |
| Git만 지난주로 이동 | v1          | v2               | 기록과 실제 입력이 다름        |
| DVC로 데이터도 복원 | v1          | v1               | 지난주 입력을 사용할 준비 완료 |

파일 이름이 `data.zip`으로 같다는 이유만으로 같은 데이터라고 판단할 수 없습니다. DVC 이름표의 내용 해시를 기준으로 실제 파일을 맞춰야 합니다.

## 복원 전에 현재 작업을 보관합니다

작업 폴더에 아직 기록하지 않은 중요한 변경이 있다면 먼저 보관하세요. 복원은 선택한 과거 상태로 파일을 바꾸는 일이므로, 지금 수정 중인 데이터를 덮어쓰지 않도록 현재 버전의 코드와 데이터가 저장되어 있는지 확인합니다.

실습 화면에서는 v1·v2가 정해져 있지만 실제 프로젝트에서는 Git 커밋이나 태그로 목표를 고릅니다. “지난주쯤의 파일”보다 **실험 ID와 커밋**을 기록해 두는 편이 정확합니다.

## 복원이 안 될 때 확인하는 순서

먼저 Git에서 원하는 커밋을 골랐는지 확인합니다. 다른 커밋의 이름표를 보고 있다면 DVC는 그 이름표가 요구하는 다른 데이터를 준비하게 됩니다.

다음으로 데이터가 어디에 남아 있는지 봅니다. `dvc checkout`은 로컬 캐시에서 내용을 꺼내므로 필요한 객체가 없으면 원격에서 가져와야 합니다. `dvc pull`도 실패한다면 원격의 객체 보관 여부, 주소와 읽기 권한을 확인합니다.

| 증상                               | 먼저 볼 곳                   |
| ---------------------------------- | ---------------------------- |
| Git을 되돌렸는데 데이터가 그대로임 | DVC 복원을 실행했는지        |
| 캐시에서 파일을 찾지 못함          | 원격에서 받을 수 있는지      |
| 원격 다운로드에 실패함             | 데이터 공유 여부와 접근 권한 |
| 데이터는 같은데 모델 점수가 다름   | 코드·설정·실행 환경          |

해시와 경로가 적힌 이름표는 내용을 찾는 데 도움을 줍니다. 그러나 캐시와 원격 모두에서 내용이 삭제되었다면 이름표만으로 파일을 되살릴 수 없습니다. 장기간 재현해야 할 데이터는 보존 정책과 백업도 함께 관리합니다.

## 복원 뒤에는 무엇을 확인할까요?

작업 폴더의 데이터가 선택한 이름표와 맞는지 확인하고, 학습 코드가 그 경로를 실제로 읽는지도 점검합니다. 다른 폴더나 별도 다운로드 경로의 파일을 읽으면 복원한 데이터가 실험에 사용되지 않을 수 있습니다.

DVC가 추적하는 상태를 점검할 때는 `dvc status`를 사용할 수 있습니다. 이것만으로 모델 점수가 지난주와 같다는 사실까지 확인되는 것은 아닙니다. 입력 상태 확인 뒤 실제 학습과 평가 결과를 비교해야 합니다.

<LessonSummary>

과거 실험을 준비할 때는 Git에서 코드와 데이터 이름표를 선택한 뒤, DVC로 실제 작업 파일도 맞춥니다. 원하는 내용이 로컬 캐시에 있으면 dvc checkout으로 꺼내고, 없으면 dvc pull로 원격에서 받아 반영합니다. 캐시와 원격 모두에 파일이 없다면 이름표만으로 복원할 수 없습니다. 파일 복원 뒤에는 학습 설정·라이브러리·난수 조건을 확인하고 모델 결과를 비교합니다.

</LessonSummary>
