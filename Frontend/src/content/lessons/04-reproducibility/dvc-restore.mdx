## 개념 이해

Git으로 과거 커밋에 이동하면 소스 코드와 DVC 메타데이터가 바뀝니다. 큰 데이터 파일은 Git이 직접 추적하지 않으므로 작업 공간은 이전 데이터를 가질 수 있습니다. 캐시에 필요한 데이터가 있으면 dvc checkout으로 맞춥니다.

> **연결 전에 예측하기** — Git 포인터는 v1이지만 캐시에 v1 파일이 없는 상황입니다. 어떤 자료를 어디서 가져와야 할까요?

<NodeExample />

연결을 따라가며 확인한 자료는 **v1 해시 · v1 실제 파일 · v1 작업 데이터**입니다. 캐시 부재와 원격 접근 실패를 구분해 조사하세요. 같은 데이터 파일을 복원한 뒤에도 동일한 학습 결과를 비교하려면 환경·파라미터·난수 조건을 함께 기록해야 합니다.

## 관찰한 결과 해석하기

캐시에 없다면 원격에서 가져오는 dvc pull이 필요합니다. 이 실험은 v1·v2가 캐시에 있다고 가정합니다. 포인터를 v1로 바꾼 것과 실제 데이터가 v1이 된 것을 따로 확인하세요.

## 명령 예제 · 포인터와 실제 파일을 순서대로 복원

Git으로 메타데이터를 되돌린 다음 필요한 데이터를 확인합니다. 로컬 캐시가 있으면 `dvc checkout`, 없으면 설정된 원격에서 dvc pull로 가져옵니다. 아래 명령은 실제 프로젝트에서 실행하는 예제이며 브라우저에서 실행되지 않습니다.

```bash
git checkout <과거-커밋>
# 캐시에 필요한 데이터가 있을 때
dvc checkout
# 필요한 데이터가 원격에 있을 때
dvc pull
```

실행 예제에서 각 명령이 변경하는 파일 또는 실행 상태를 확인한 뒤, 위에서 설명한 흐름과 비교해 보세요.

## 적용 조건과 한계

Git 체크아웃은 메타데이터를 바꾸며 DVC 체크아웃은 캐시의 실제 내용을 작업 공간에 반영합니다. 필요한 내용이 캐시에 없으면 원격에서 가져와야 합니다. 환경·난수·외부 입력까지 고정하지 않으면 동일한 학습 결과는 보장되지 않습니다.

DVC가 추적하는 실제 데이터는 .gitignore로 Git 추적에서 제외합니다. .dvcignore는 DVC가 탐색하지 않을 경로를 지정하는 별도 파일입니다. 캐시는 내용 단위로 재사용하며 모든 바이너리의 변경 바이트만 저장한다고 가정하지 않습니다.
