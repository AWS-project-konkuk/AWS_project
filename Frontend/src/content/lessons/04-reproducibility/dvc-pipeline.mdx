## 학습 횟수만 바꿨는데 자료 준비도 다시 해야 할까요?

사진 크기를 맞추고, 모델을 학습하고, 점수를 확인하는 작업이 있습니다. 학습 횟수만 10회에서 20회로 바꿨다면 사진 크기를 다시 맞출 필요는 없겠죠.

이처럼 **순서대로 이어지는 작업을 파이프라인**이라고 합니다. DVC는 각 작업이 무엇을 읽고 무엇을 만드는지 기록해 재사용할 결과를 찾습니다.

그림에서 앞 단계의 결과가 다음 단계의 재료가 됩니다. 자료 준비 방법이 바뀌면 학습도 영향을 받지만, 학습 횟수만 바뀌었다면 준비한 자료는 그대로 쓸 수 있습니다.

앞 단계의 결과가 다음 단계의 입력이 되는 관계를 **의존성**이라고 합니다. 예를 들어 학습은 준비된 사진을 사용하고, 평가는 학습한 모델을 사용합니다.

## 세 파일의 역할을 알아봅시다

| 파일          | 쉽게 말하면 | 적는 내용                               |
| ------------- | ----------- | --------------------------------------- |
| `dvc.yaml`    | 작업 순서표 | 실행 명령, 필요한 입력, 만들어지는 결과 |
| `params.yaml` | 설정 메모   | 학습 횟수, 학습률 같은 값               |
| `dvc.lock`    | 실행 기록   | 실행에 사용한 입력·설정과 결과의 상태   |

학습 횟수나 학습률처럼 학습 방법을 조절하는 값을 **하이퍼파라미터**라고 부릅니다. `params.yaml`은 이런 값을 한곳에서 관리하는 설정 메모입니다. 파일을 만들기만 하면 프로그램에 자동 적용되는 것은 아니므로, 학습 코드도 이 설정을 읽도록 작성해야 합니다.

DVC는 바뀐 입력과 그 결과를 사용하는 작업을 확인합니다. 이전에 같은 조건으로 만든 결과가 캐시에 있으면 계산을 줄일 수도 있습니다.

<details>
<summary>dvc.yaml과 params.yaml 예시 보기</summary>

학습 코드는 아래 설정 파일을 읽도록 작성되어 있다고 가정합니다.

```yaml
# dvc.yaml
stages:
  train:
    cmd: python train.py
    deps: [train.py, data/prepared.csv]
    params: [train.epochs]
    outs: [model.pkl]
```

```yaml
# params.yaml
train:
  epochs: 20
```

`cmd`는 실행할 명령, `deps`는 필요한 파일, `params`는 확인할 설정, `outs`는 만들어질 결과입니다. `dvc repro`로 변경된 작업을 확인하고 필요한 단계를 실행합니다.

## 세 단계가 주고받는 자료

사진 분류 예시를 조금 더 구체적으로 나눠 보겠습니다.

| 단계      | 필요한 입력                     | 만들어지는 결과            |
| --------- | ------------------------------- | -------------------------- |
| 자료 준비 | 원본 사진, 전처리 코드          | 크기를 맞춘 학습·평가 자료 |
| 모델 학습 | 학습 자료, 학습 코드, 학습 설정 | 모델 파일                  |
| 점수 확인 | 모델, 별도 평가 자료, 평가 코드 | 정확도 같은 평가 지표      |

평가에는 모델만 필요한 것이 아닙니다. **무엇으로 평가했는지**도 결과에 영향을 줍니다. 학습에 쓰지 않은 평가 자료를 따로 준비하고 그 버전도 기록합니다.

이 관계를 적어 두면 어떤 입력이 바뀌었을 때 어느 결과를 다시 확인해야 하는지 알 수 있습니다. 학습 코드만 바뀌면 준비한 자료는 그대로 쓸 수 있지만 새 모델과 그 점수는 다시 확인합니다.

## 학습 횟수를 바꾸는 예를 따라가 봅시다

처음에는 `epochs: 10`으로 학습했습니다. 사진과 전처리 방법은 그대로 두고 이 값을 `20`으로 바꿉니다. 학습 코드는 `params.yaml`을 읽고, DVC에는 해당 설정을 추적하도록 적어 둔 상태라고 가정합니다.

1. DVC가 추적 중인 학습 횟수가 바뀌었는지 확인합니다.
2. 자료 준비에 필요한 입력은 그대로이므로 준비한 자료를 재사용할 수 있습니다.
3. 학습 단계는 새 횟수로 모델을 만듭니다.
4. 모델의 내용이 바뀌면 이를 사용하는 평가 단계도 영향을 받습니다.

기존 결과와 완전히 같은 파일이 나오는 경우에는 뒤 단계가 다시 계산될 필요가 줄어들 수 있습니다.

## 다운로드 재사용과 계산 재사용은 다릅니다

캐시라는 말이 나오면 두 가지를 나눠 생각해 보세요.

| 재사용하는 것                   | 줄일 수 있는 작업                       |
| ------------------------------- | --------------------------------------- |
| 내 캐시에 있는 데이터 내용      | 같은 파일을 원격에서 다시 내려받기      |
| 같은 입력·명령·설정의 실행 결과 | 이미 했던 전처리나 학습을 다시 계산하기 |

데이터가 캐시에 있다는 사실만으로 학습을 건너뛸 수 있는 것은 아닙니다. 학습 설정이 달라졌다면 다른 결과가 필요합니다. 반대로 같은 조건의 실행 결과와 출력이 남아 있으면 그 결과를 재사용할 수 있습니다.

데이터 원격에서 출력 파일을 받는 일과 파이프라인을 실행하는 일도 구분합니다. `dvc pull`은 필요한 파일을 준비하고, `dvc repro`는 선언한 작업의 변경 여부를 확인해 필요한 단계를 실행합니다. DVC가 모든 외부 입력을 알아서 다운로드한다고 가정하지 마세요.

### 캐시가 있는 경우와 없는 경우를 순서대로 생각하기

1. 먼저 선택한 Git 기록의 데이터 이름표와 실행 기록을 확인합니다.
2. 필요한 내용이 내 캐시에 있으면 작업 폴더에 꺼내 쓸 수 있습니다.
3. 캐시에 없지만 데이터 원격에 공유되어 있다면 `dvc pull`로 받습니다.
4. 입력 파일이 준비되면 `dvc repro`로 바뀐 작업과 재사용할 결과를 판단합니다.

**다운로드를 생략할 수 있는지**와 **계산을 생략할 수 있는지**는 다른 질문입니다. 원본 사진이 캐시에 있어도 새 학습 설정의 결과는 없을 수 있습니다. 반대로 필요한 실행 기록과 출력이 남아 있다면 같은 조건의 계산 결과를 재사용할 수 있습니다.

<LessonSummary>

파이프라인은 자료 준비·학습·평가가 입력과 결과로 이어지는 흐름입니다. dvc.yaml에는 작업과 필요한 입력을, params.yaml에는 설정을, dvc.lock에는 실행 상태를 기록합니다. DVC는 선언된 입력을 기준으로 변경과 결과 재사용을 판단합니다. 학습 설정만 달라졌다면 자료 준비 결과를 재사용할 수 있지만 원본이나 전처리가 바뀌면 뒤 단계도 확인해야 합니다.

</LessonSummary>
