## 문제 상황

학습 코드 한 줄을 바꿨는데 데이터 다운로드와 전처리까지 매번 다시 실행됩니다. 반대로 필요한 재학습을 건너뛰면 오래된 모델을 평가할 수 있습니다.

## 개념과 동작 원리

dvc.yaml은 단계의 명령(cmd), 의존 자료(deps), 결과(outs), 추적할 파라미터(params)를 정의합니다. dvc.lock은 실행에 사용한 상태를 기록합니다. DVC는 선언한 의존성을 기준으로 변경과 캐시 재사용 가능성을 판단하므로 누락한 입력은 자동으로 알아내지 못합니다.

## 자료와 요청의 흐름

원본 데이터 → 전처리 결과 → 학습 모델 → 평가 결과의 의존성을 추적합니다. 학습 코드만 바뀌면 전처리를 재사용할 수 있고 학습과 그 결과에 의존하는 평가가 영향을 받습니다. 이미 존재하는 실행 캐시·출력 캐시를 재사용할 수 있는 조건과 새로 계산해야 하는 조건을 구분합니다.

```yaml
stages:
  train:
    cmd: python train.py
    deps: [train.py, data/prepared.csv]
    params: [learning_rate]
    outs: [model.pkl]
```

실행 예제에서 각 명령이 변경하는 파일 또는 실행 상태를 확인한 뒤, 위에서 설명한 흐름과 비교해 보세요.

> **연결 전에 예측하기** — 각 연결은 의존하는 입력입니다. 준비한 자료와 학습 결과가 평가까지 어떻게 이어지는지 확인하세요.

<NodeExample />

연결을 따라가며 확인한 자료는 **학습 자료 · 학습 모델 · 별도 평가 자료**입니다. 학습 코드만 바뀌면 전처리 결과를 재사용할 수 있지만 데이터가 바뀌면 하류도 영향을 받습니다. 빠뜨린 의존성은 자동으로 추론되지 않으므로 입력 선언부터 확인합니다.

## 비교와 한계

Git 체크아웃은 메타데이터를 바꾸며 DVC 체크아웃은 캐시의 실제 내용을 작업 공간에 반영합니다. 필요한 내용이 캐시에 없으면 원격에서 가져와야 합니다. 환경·난수·외부 입력까지 고정하지 않으면 동일한 학습 결과는 보장되지 않습니다.

## 전체 과정과 연결

지난주 모델을 재현하려고 코드만 되돌리면 데이터는 최신 버전으로 남을 수 있습니다. 코드·데이터·파라미터·라이브러리 환경을 함께 식별해야 어떤 실험인지 설명할 수 있습니다. Git은 코드와 작은 메타데이터를, DVC는 데이터 내용과 캐시·원격의 대응을 관리합니다. 파일 복원과 학습을 다시 실행했을 때의 수치 재현성은 구분해야 합니다.
