## 문제 상황

원본 정리, 전처리, 학습, 평가를 매번 처음부터 실행하고 있습니다. 학습 코드만 바뀌었는데 전처리까지 다시 수행하면 시간과 비용이 낭비됩니다. DVC 파이프라인은 단계의 명령·의존성·출력을 기록해 어느 단계부터 다시 실행해야 하는지 판단합니다.

## 개념과 동작 원리

### 'dvc.yaml'과 'params.yaml'

'dvc.yaml'은 실행 단계를 정의하고 'params.yaml'은 실험에서 바꿀 설정값을 모읍니다.

```yaml
stages:
  preprocess:
    cmd: python preprocess.py
    deps: [raw, preprocess.py]
    params: [preprocess.resize]
    outs: [prepared]
  train:
    cmd: python train.py
    deps: [prepared, train.py]
    params: [train.epochs, train.learning_rate]
    outs: [model.bin]
  evaluate:
    cmd: python evaluate.py
    deps: [model.bin, test]
    metrics: [metrics.json]
```

```yaml
preprocess:
  resize: 224
train:
  epochs: 20
  learning_rate: 0.001
```

### 변경에 따른 재실행

- 원본이나 전처리 코드가 바뀌면 전처리부터 학습·평가까지 영향을 받습니다.
- 학습 코드나 학습 파라미터가 바뀌면 학습과 평가를 다시 실행합니다.
- 평가 코드만 바뀌면 평가 단계만 다시 실행할 수 있습니다.
- 입력·명령·파라미터가 같고 출력이 캐시에 있으면 이전 결과를 복원할 수 있습니다.

<NodeExample />

캐시는 “바뀐 코드 줄만 실행”하는 기능이 아닙니다. DVC는 단계의 의존성 상태를 비교하고 변경된 단계와 그 출력을 사용하는 하위 단계를 다시 실행하거나 캐시 결과를 복원합니다.

### 재현성에 필요한 기록

'dvc.yaml'과 'params.yaml'만으로 Python 환경, 외부 서비스, 난수와 GPU 연산의 결정성까지 자동 고정되지는 않습니다. 코드·데이터·파라미터와 함께 패키지 버전, 컨테이너 이미지와 난수 설정도 기록해야 합니다.

## 비교와 한계

- 단계 캐시는 입력과 명령이 같을 때 이전 출력을 재사용하며 모든 실행을 생략하는 기능은 아닙니다.
- 외부 API나 데이터베이스처럼 선언하지 않은 입력은 변경 여부를 판단하기 어렵습니다.
- 코드·데이터가 같아도 실행 환경과 난수 조건이 다르면 결과가 달라질 수 있습니다.

## 전체 과정과 연결

파이프라인은 데이터가 만들어지는 과정을 재현합니다. 다음 강의에서는 Git에서 과거 포인터를 선택한 뒤 캐시와 데이터 원격을 이용해 그 시점의 실제 파일을 작업 공간에 되돌립니다.

<LessonSummary>

DVC 파이프라인은 'dvc.yaml'에 전처리·학습·평가 단계의 명령, 의존성, 파라미터와 출력을 기록합니다. 'params.yaml'은 실험 설정을 코드 밖에서 버전 관리하게 합니다. DVC는 변경된 입력이 영향을 주는 단계부터 하위 단계를 다시 실행하고 조건이 같은 출력이 로컬 캐시에 있으면 재사용하여 전체 재실행 비용을 줄입니다.

</LessonSummary>
