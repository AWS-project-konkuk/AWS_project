## 개념 이해

Git은 코드와 변경 이력을 추적하기에 적합합니다. 큰 바이너리가 자주 바뀌면 이력이 커지고 복제·전송·관리 부담이 증가합니다. 단순한 파일 크기 하나만이 아니라 변경 횟수와 데이터 특성도 중요합니다.

## 관찰한 결과 해석하기

현재 버전에서 파일을 지워도 이전 커밋이 참조하는 객체가 즉시 모두 사라지지 않습니다. 아래 계산은 바이너리 버전별 전체 복사라는 단순 예시이며 Git의 압축·델타 처리나 호스팅 제공자의 파일 제한을 그대로 재현하지 않습니다.

## 적용 조건과 한계

Git 체크아웃은 메타데이터를 바꾸며 DVC 체크아웃은 캐시의 실제 내용을 작업 공간에 반영합니다. 필요한 내용이 캐시에 없으면 원격에서 가져와야 합니다. 환경·난수·외부 입력까지 고정하지 않으면 동일한 학습 결과는 보장되지 않습니다.

DVC가 추적하는 실제 데이터는 .gitignore로 Git 추적에서 제외합니다. .dvcignore는 DVC가 탐색하지 않을 경로를 지정하는 별도 파일입니다. 캐시는 내용 단위로 재사용하며 모든 바이너리의 변경 바이트만 저장한다고 가정하지 않습니다.

## 전체 과정과 연결하기

코드와 작은 설정은 Git 이력으로 추적하기 좋지만 큰 바이너리가 반복 변경되면 복제와 전송 부담이 커집니다. 파일 크기뿐 아니라 변경 빈도와 과거 내용의 보관 요구를 함께 판단해야 합니다.
