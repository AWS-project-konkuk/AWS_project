## GPU가 두 장인데 학습 시간은 왜 반으로 안 줄까요?

사진 묶음을 절반씩 나눠 GPU 두 장에 맡겼습니다. 계산만 보면 두 장이 각자 빨리 끝냈는데, 다음 학습 단계로 넘어가기 전에 둘 다 멈춰 기다립니다. 사진은 이미 나눠 줬는데, 두 GPU는 이제 무엇을 주고받는 걸까요?

## 개념 이해

**데이터 병렬**(Data Parallelism)은 학습할 데이터가 많을 때 학습 속도를 높이기 위한 방법입니다. 각 GPU에 같은 모델을 복제하고, 배치를 GPU 수만큼 나누어 서로 다른 데이터를 처리합니다.

한 step은 다음 순서로 진행됩니다.

1. 배치 64를 두 GPU에 32개씩 나눕니다.
2. 각 GPU가 자기 몫으로 forward·backward를 수행해 기울기 g0, g1을 얻습니다.
3. **All-Reduce**로 기울기를 모아 평균 `(g0 + g1) / 2`를 구하고, 모든 GPU가 같은 평균을 받습니다.
4. 각 GPU가 같은 기울기로 optimizer step을 수행하므로 가중치가 계속 똑같이 유지됩니다.

여기서 평균내는 것은 **가중치가 아니라 기울기**입니다. 모든 복제본이 같은 기울기로 같은 갱신을 하기 때문에 가중치를 다시 나눠 줄 필요가 없습니다. PyTorch의 `DistributedDataParallel`(DDP)은 이 과정을 GPU마다 프로세스 하나씩 띄워 수행하고, 통신은 NCCL이 맡습니다.

> **연결 전에 예측하기** — 각 GPU에는 전체 모델이 복제되어 있다고 가정합니다. 서로 다른 데이터로 구한 기울기를 모으는 흐름을 확인하세요.

<NodeExample />

연결을 따라가며 확인한 자료는 **기울기 g1 · 기울기 g2**입니다. 처리량을 높이는 목적과 모델을 여러 장치에 나눠 담는 목적을 구분합니다. 동기화 비용과 데이터 공급이 커지면 GPU를 추가해도 선형으로 빨라지지 않습니다.

DDP는 backward가 끝날 때까지 기다리지 않습니다. 기울기를 **버킷** 단위로 묶어, 뒤쪽 레이어의 기울기가 준비되는 대로 All-Reduce를 시작해 계산과 통신을 겹칩니다. 그래서 GPU 간 연결이 빠를수록, 모델이 클수록 통신을 잘 숨길 수 있는지가 확장성을 좌우합니다.

```python
# torchrun --nproc_per_node=2 train.py
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data.distributed import DistributedSampler

dist.init_process_group("nccl")
rank = dist.get_rank()
model = DDP(model.to(rank), device_ids=[rank])          # 모델 복제
sampler = DistributedSampler(dataset)                    # 데이터를 GPU별로 나눔
loader = DataLoader(dataset, batch_size=32, sampler=sampler)
```

## 관찰한 결과 해석하기

GPU 수가 늘어도 한 장당 모델 복제본 메모리는 없어지지 않습니다. 작업 분할로 연산 시간이 줄어도 기울기 통신이 새 병목이 될 수 있습니다. GPU 수와 통신 비용을 함께 바꾸고 선형 가속이 깨지는 지점을 관찰하세요.

<Activity />

모델 크기를 GPU당 VRAM보다 크게 하면 GPU 수와 관계없이 실패합니다. 데이터 병렬은 데이터를 나눌 뿐, 각 GPU가 **모델·기울기·옵티마이저 상태 전체**를 가지기 때문입니다.

## 적용 조건과 한계

- **유효 배치가 GPU 수만큼 커짐**: GPU당 32개 × 2장이면 유효 배치 64입니다. 학습률과 warmup을 다시 조정해야 할 수 있습니다.
- **통신 비용**: 매 step마다 파라미터 크기만큼의 기울기를 주고받습니다. PCIe로만 연결된 GPU나 여러 노드에 걸친 학습에서는 통신이 병목이 되기 쉽습니다.
- **데이터 공급**: GPU가 늘어난 만큼 데이터 로더도 빨라져야 합니다. 저장소·전처리가 따라오지 못하면 GPU가 기다립니다.
- **메모리 중복**: 모든 GPU가 같은 모델 상태를 중복해서 가집니다. 이 중복을 없애려면 ZeRO·FSDP처럼 데이터 병렬이면서 가중치·기울기·옵티마이저 상태를 GPU마다 나누어 갖는 방식을 씁니다.
- `torch.nn.DataParallel`은 한 프로세스가 여러 GPU를 다루는 옛 방식으로, 보통 DDP가 더 빠르고 권장됩니다.

## 전체 과정과 연결하기

데이터 병렬은 각 GPU에 같은 모델을 두고 다른 배치를 계산한 뒤 기울기를 평균내 모델을 갱신합니다. 모델이 GPU 한 장에 들어갈 때 학습 속도를 높이는 가장 기본적인 전략이며, 모델이 들어가지 않으면 다음 강의의 모델 병렬·텐서 병렬이 필요합니다.

<Callout title="판단할 때 확인하기">

처리량을 높이는 목적과 모델을 여러 장치에 나눠 담는 목적을 구분합니다. 데이터 병렬은 앞의 목적을 위한 전략입니다.

</Callout>

<LessonSummary>

데이터 병렬은 각 GPU에 같은 모델을 복제하고 배치를 나누어 계산한 뒤, All-Reduce로 기울기를 평균내 모든 복제본을 같은 값으로 갱신합니다. 가중치를 평균내는 것이 아니라 기울기를 평균낸다는 점, 그리고 각 GPU가 모델 학습 상태 전체를 담아야 한다는 점이 핵심입니다.
