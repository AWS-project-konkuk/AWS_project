## GPU로 옮겼는데 왜 더 느릴까요?

집 컴퓨터에서 사진 수천 장을 분류하려니 CPU로는 한참 걸려 GPU로 옮겼습니다. 전체 사진을 돌릴 땐 빨라졌는데, 테스트용 사진 한 장만 넣었더니 오히려 CPU가 먼저 끝납니다. 방금까지 빠르던 GPU가 사진 한 장 앞에서 왜 뒤처질까요?

## 개념 이해

CPU는 적은 수의 강력한 코어로 복잡하고 다양한 작업을 처리하는 데 적합합니다. 반면 GPU는 많은 연산 유닛으로 동일하거나 유사한 연산을 동시에 처리하는 데 적합합니다. 이러한 차이가 작업 규모에 따라 성능 차이를 만드는 원인이 됩니다.

| 구분        | CPU                               | GPU                                  |
| ----------- | --------------------------------- | ------------------------------------ |
| 주요 특징   | 적은 수의 고성능 코어             | 많은 수의 연산 유닛                  |
| 설계 목표   | 한 작업을 빨리 끝내기 (지연 시간) | 많은 작업을 한꺼번에 끝내기 (처리량) |
| 강점        | 복잡한 제어와 다양한 작업         | 대규모 병렬 연산                     |
| 적합한 작업 | 순차 처리, 복잡한 로직            | 행렬 연산, 딥러닝                    |
| 고려 사항   | 병렬 처리량의 한계                | 준비 및 데이터 전송 비용             |

CPU 안에는 산술·논리 연산을 하는 **ALU**, 메모리에서 명령어를 읽어 해석하고 제어 신호를 보내는 **제어 장치**, 연산 중간값을 담는 **레지스터**가 있습니다. 여기에 큰 캐시와 분기 예측 같은 장치가 더해져, 다음에 무엇을 할지 예측하기 어려운 코드도 빠르게 실행합니다.

GPU는 **SM(Streaming Multiprocessor)** 여러 개로 이루어집니다. SM 하나에는 다음이 들어 있습니다.

- **CUDA 코어**: 부동소수점 덧셈·곱셈 같은 기본 연산을 하는 단순한 코어입니다. 하나는 CPU 코어보다 약하지만 수천 개가 동시에 일합니다.
- **Tensor Core**: 작은 행렬 조각의 곱셈과 덧셈(`D = A × B + C`)을 한 번에 처리하는 전용 장치입니다. 큰 행렬 곱셈은 이 작은 조각 연산을 반복해서 계산하며, FP16·BF16·FP8 같은 낮은 정밀도에서 특히 빠릅니다.
- **Warp Scheduler, Register File, Shared Memory/L1**: 스레드를 32개씩 묶은 **워프**(warp)에 명령을 내리고, 워프들이 레지스터와 공유 메모리를 나눠 씁니다.

### 한 명령어로 여러 데이터를 처리하기 (SIMD와 SIMT)

딥러닝 계산의 대부분은 행렬 곱셈입니다. 행렬 곱셈은 서로 독립적인 "곱하고 더하기"를 엄청나게 많이 반복하므로, **같은 명령을 여러 데이터에 동시에 적용**할 수 있으면 빨라집니다.

<Figure
  src="images/lessons/05-gpu/cpu-gpu/simd-simt.svg"
  alt="스칼라 실행은 ADD 명령을 네 번 실행하고, SIMD는 벡터 레지스터의 값 네 개를 ADD 명령 한 번으로 처리하며, SIMT는 32개 스레드로 이루어진 워프가 FMA 명령 하나를 동시에 실행하는 비교 그림"
  caption="SIMD는 CPU의 벡터 명령, SIMT는 GPU가 워프 단위로 스레드를 실행하는 방식입니다."
/>

- **SIMD(Single Instruction, Multiple Data)**: 명령어 하나로 벡터 레지스터에 담긴 여러 값을 한꺼번에 계산합니다. CPU의 AVX(x86), NEON(ARM) 명령어가 여기에 해당합니다. CPU도 병렬 계산을 할 수 있다는 뜻입니다.
- **SIMT(Single Instruction, Multiple Threads)**: NVIDIA GPU의 실행 방식입니다. 프로그래머는 스레드 하나의 코드를 작성하고, GPU는 스레드 32개를 한 워프로 묶어 같은 명령을 동시에 실행합니다. 워프 안에서 `if` 분기가 갈리면 두 경로를 차례로 실행해야 하므로 느려집니다(분기 발산).

결국 GPU가 빠른 이유는 개별 코어가 빨라서가 아니라, 같은 연산을 수천 개 스레드에 동시에 적용할 수 있기 때문입니다.

이처럼 CPU와 GPU는 서로 다른 구조와 장점을 가지고 있습니다. 그렇다면 이러한 차이가 실제 처리 시간에도 영향을 줄까요?

## 관찰한 결과 해석하기

연산 개수를 바꾸면서 CPU와 GPU의 처리 시간을 비교해 보세요.
GPU의 연산 시간만 보는 것이 아니라, 준비 및 데이터 전송에 필요한 시간까지 함께 비교해 보세요.

<Activity />

연산 개수가 적으면 GPU 준비와 데이터 전송 비용이 병렬 처리로 얻는 이득보다 커서 오히려 느릴 수 있습니다. 연산 개수가 늘수록 같은 시간에 처리하는 양의 차이가 커져 GPU가 유리해집니다. 이 활동은 실제 하드웨어 벤치마크가 아니라 원리를 보여 주는 단순화한 모형입니다. 실제로 측정할 때는 GPU 연산이 비동기로 실행되므로 `torch.cuda.synchronize()`를 호출한 뒤 시간을 재야 정확합니다.

## 적용 조건과 한계

- **데이터 전송**: CPU 메모리의 데이터를 GPU로 옮기는 PCIe 전송은 GPU 내부 메모리 대역폭보다 훨씬 느립니다. 작은 텐서를 자주 주고받으면 전송 시간이 연산 시간보다 길어집니다.
- **커널 실행 비용**: GPU 연산 하나하나(커널)를 시작하는 데에도 고정 비용이 있습니다. 작은 연산을 여러 번 호출하는 코드는 GPU를 충분히 활용하지 못합니다.
- **병렬화할 수 없는 작업**: 앞의 결과가 있어야 다음을 계산할 수 있는 순차 로직, 분기가 많은 전처리는 여전히 CPU가 맡는 편이 낫습니다.
- **GPU는 연산 장치일 뿐**: 데이터를 읽고 전처리하는 CPU·저장소가 느리면 GPU는 기다립니다. GPU 사용률이 낮다면 데이터 공급부터 확인합니다.

## 전체 과정과 연결하기

학습 작업에서 CPU는 데이터 로딩·전처리와 전체 흐름의 제어를, GPU는 순전파·역전파의 대량 행렬 연산을 맡습니다. GPU를 고를 때도 "얼마나 빠른가"뿐 아니라 데이터를 얼마나 빨리 공급할 수 있는지, 작업이 GPU를 채울 만큼 큰지를 함께 판단해야 합니다.

<Callout title="판단할 때 확인하기">

연산 시간만 보지 말고 데이터 준비와 장치 전송까지 측정합니다. 작은 작업에서는 추가 비용이 이득보다 클 수 있습니다.

</Callout>

<LessonSummary>

CPU는 적은 수의 강력한 코어로 다양한 제어 흐름을 빠르게 처리하고, GPU는 SM 안의 수많은 코어와 Tensor Core로 같은 연산을 많은 데이터에 동시에 적용합니다. GPU는 SIMT 방식으로 스레드 32개를 한 워프로 묶어 실행하기 때문에, 독립적인 곱셈·덧셈이 반복되는 행렬 연산에 특히 강합니다.

- **다시 판단해 보기** — GPU 사용에는 준비·메모리 이동 비용이 있어 작업 규모에 따라 전체 실행 시간이 달라집니다. 연산 시간만 보지 말고 데이터 준비와 장치 전송까지 측정해 실제 처리량으로 선택하세요.
