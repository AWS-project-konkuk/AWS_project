## 큰 모델을 둘로 나누면 어디서 잘라야 할까요?

학습을 시작하자 모델 전체가 GPU 한 장에 들어가지 않습니다. 옆에는 빈 GPU가 있지만 같은 모델을 복사하기에는 그쪽도 작습니다. 앞쪽 레이어와 뒤쪽 레이어를 각각 맡긴다면, 두 GPU는 어디서 계산을 이어받아야 할까요?

## 개념 이해

**모델 병렬**(Model Parallelism)은 하나의 모델을 여러 GPU에 나누어 올리는 방법입니다. 데이터 병렬이 학습 속도를 높이기 위한 방법이라면, 모델 병렬은 **한 GPU에 들어가지 않는 큰 모델을 돌리기 위한** 방법입니다.

모델을 나누는 방향은 두 가지입니다.

| 방식                             | 나누는 단위         | 예                           |
| -------------------------------- | ------------------- | ---------------------------- |
| 레이어 간 분할 (파이프라인 병렬) | 레이어 묶음         | GPU 1에 L1-L4, GPU 2에 L5-L8 |
| 레이어 내부 분할 (텐서 병렬)     | 한 레이어 안의 행렬 | 다음 강의에서 다룸           |

이 강의에서는 앞 레이어와 뒤 레이어를 나누는 방식을 다룹니다.

<Figure
  src="images/lessons/05-gpu/model-parallel/mechanism.svg"
  alt="GPU 1에 레이어 L1부터 L4, GPU 2에 L5부터 L8을 배치하고, 순전파에서는 활성값이 GPU 1에서 GPU 2로, 역전파에서는 기울기가 GPU 2에서 GPU 1로 이동하는 그림"
  caption="경계를 넘는 것은 경계 레이어의 활성값(순전파)과 그 기울기(역전파)입니다."
/>

각 GPU는 자기 레이어의 가중치·기울기·옵티마이저 상태만 가지므로 장치당 메모리가 대략 절반이 됩니다. 대신 GPU 1이 L4까지 계산을 끝내야 GPU 2가 L5를 시작할 수 있고, 역전파에서는 순서가 반대가 됩니다. 이 의존성 때문에 단순하게 나누기만 하면 **한 번에 GPU 하나만 일하고 나머지는 기다립니다.**

```python
class TwoGPUModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.front = nn.Sequential(...).to("cuda:0")   # L1~L4
        self.back = nn.Sequential(...).to("cuda:1")    # L5~L8

    def forward(self, x):
        h = self.front(x.to("cuda:0"))
        return self.back(h.to("cuda:1"))               # 활성값을 다음 GPU로 전송
```

메모리를 나눠 쓸 수 있어도 단순한 레이어 분할만으로 GPU들이 동시에 일하지는 않습니다. 이 대기를 줄이는 것이 **파이프라인 병렬**입니다. 배치를 여러 마이크로배치로 나누어, GPU 1이 두 번째 마이크로배치를 계산하는 동안 GPU 2가 첫 번째를 계산하게 합니다.

## 적용 조건과 한계

- **파이프라인 버블**: 파이프라인을 채우고 비우는 앞뒤 구간에는 여전히 대기가 남습니다. 마이크로배치를 늘리면 버블 비율은 줄지만, 마이크로배치마다 경계 활성값을 보관·전송해야 해서 메모리와 통신이 늘어납니다.
- **계산 불균형**: 레이어마다 계산량이 다르면 느린 GPU에 맞춰 전체가 기다립니다. 레이어를 GPU 수에 맞춰 균등하게 나누는 것 자체가 설계 문제입니다.
- **통신량**: 경계에서 주고받는 것은 활성값 하나뿐이라 텐서 병렬보다 통신이 적습니다. 그래서 연결이 상대적으로 느린 노드 사이에도 쓸 수 있습니다.
- 메모리 수용 문제를 해결해도 순차 의존성 때문에 GPU 두 장이 한 장보다 두 배 빠르지는 않습니다.

## 전체 과정과 연결하기

모델의 앞쪽과 뒤쪽 레이어를 다른 GPU에 배치하면 각 장치가 전체 모델을 보관할 필요가 줄어듭니다. 앞부분의 결과 활성값이 다음 장치로 전달되어야 뒤 연산을 진행할 수 있으며, 파이프라인 병렬은 마이크로배치를 겹쳐 그 대기를 줄입니다.

<Callout title="판단할 때 확인하기">

장치 간 통신과 대기 구간을 함께 측정하세요. 각 GPU의 사용률이 번갈아 오르내린다면 파이프라인 버블이 큰 상태입니다.

</Callout>

<LessonSummary>

모델 병렬은 한 GPU에 들어가지 않는 모델을 여러 GPU에 나누어 올리는 방법이며, 레이어 묶음을 장치별로 나누면 경계에서 활성값(순전파)과 그 기울기(역전파)를 주고받습니다. 단순 분할은 한 번에 한 GPU만 일하게 만들고, 파이프라인 병렬은 마이크로배치를 겹쳐 이 대기를 줄입니다.
