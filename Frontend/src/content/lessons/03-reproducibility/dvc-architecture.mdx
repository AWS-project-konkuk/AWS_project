그림의 **Git 메타데이터**, **캐시**, **데이터 원격**에 주목해 보세요. Git에는 코드와 데이터 내용의 식별 정보를 기록하고, 실제 데이터는 캐시와 원격 저장소에 둡니다.

## 개념 이해

DVC는 데이터 내용의 식별 정보를 메타데이터로 추적하고 실제 파일은 캐시나 원격 저장소에 보관합니다. Git에는 소스 코드와 .dvc 같은 작은 메타데이터를 커밋합니다. .dvc 파일 자체가 S3에만 저장되는 것은 아닙니다.

## 관찰한 결과 해석하기

dvc push는 필요한 데이터를 원격에 공유하고 dvc pull은 원격에서 필요한 데이터를 가져옵니다. 코드 커밋과 데이터 해시가 함께 있어야 과거 실험의 재료를 찾을 수 있습니다. 실제 재현에는 라이브러리·난수·실행 환경도 영향을 줍니다.

## 적용 조건과 한계

Git 체크아웃은 메타데이터를 바꾸며 DVC 체크아웃은 캐시의 실제 내용을 작업 공간에 반영합니다. 필요한 내용이 캐시에 없으면 원격에서 가져와야 합니다. 환경·난수·외부 입력까지 고정하지 않으면 동일한 학습 결과는 보장되지 않습니다.

DVC가 추적하는 실제 데이터는 .gitignore로 Git 추적에서 제외합니다. .dvcignore는 DVC가 탐색하지 않을 경로를 지정하는 별도 파일입니다. 캐시는 내용 단위로 재사용하며 모든 바이너리의 변경 바이트만 저장한다고 가정하지 않습니다.

## 전체 과정과 연결하기

Git에는 코드와 데이터 내용의 식별 정보를 기록하고, 실제 데이터는 캐시와 원격 저장소에 둡니다. 메타데이터가 어떤 내용을 요구하는지 확인한 뒤 로컬 또는 원격에서 그 내용을 확보합니다.
