## 개념과 동작 원리

Data Warehouse는 관리된 분석 테이블을, Data Lake는 다양한 원본 데이터를 담는 저장 기반을 강조합니다. Lakehouse는 데이터 레이크에 테이블 포맷·카탈로그·처리 엔진 등을 결합해 테이블 단위 관리와 분석을 지원하는 아키텍처입니다. Object Storage 자체가 테이블 트랜잭션을 제공하는 것은 아닙니다.

## 자료와 요청의 흐름

파일 저장소 위의 Iceberg·Delta Lake 같은 테이블 포맷이 스냅샷이나 로그로 유효한 파일 집합과 스키마를 관리합니다. 과거 스냅샷을 고정하면 같은 시점의 데이터를 읽을 수 있습니다. 보존 정책으로 과거 파일이 삭제되면 타임트래블도 제한되며 스키마 진화가 모든 소비 코드의 호환성을 보장하지 않습니다.

## 비교와 한계

Git 체크아웃은 메타데이터를 바꾸며 DVC 체크아웃은 캐시의 실제 내용을 작업 공간에 반영합니다. 필요한 내용이 캐시에 없으면 원격에서 가져와야 합니다. 환경·난수·외부 입력까지 고정하지 않으면 동일한 학습 결과는 보장되지 않습니다.

## 전체 과정과 연결

지난주 모델을 재현하려고 코드만 되돌리면 데이터는 최신 버전으로 남을 수 있습니다. 코드·데이터·파라미터·라이브러리 환경을 함께 식별해야 어떤 실험인지 설명할 수 있습니다. Git은 코드와 작은 메타데이터를, DVC는 데이터 내용과 캐시·원격의 대응을 관리합니다. 파일 복원과 학습을 다시 실행했을 때의 수치 재현성은 구분해야 합니다.
