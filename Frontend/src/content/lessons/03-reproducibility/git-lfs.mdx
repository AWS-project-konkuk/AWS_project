그림의 **Git 포인터**, **LFS 저장소**, **작업 파일**에 주목해 보세요. Git LFS는 Git 이력에 작은 포인터를 기록하고 실제 큰 파일은 별도 저장소에 보관합니다.

## 개념 이해

Git LFS는 큰 파일 대신 작은 텍스트 포인터를 Git 이력에 넣고 실제 내용은 별도 저장소에 둡니다. Git으로 코드와 포인터를 관리하면서 필요한 실제 파일을 가져오는 구조입니다.

| 방식     | Git에 기록             | 실제 파일        |
| -------- | ---------------------- | ---------------- |
| 일반 Git | 파일 객체와 이력       | Git 객체 저장소  |
| Git LFS  | 작은 텍스트 포인터     | LFS 저장소       |
| DVC      | 코드·데이터 메타데이터 | 캐시·데이터 원격 |

## 관찰한 결과 해석하기

포인터가 작아져도 실제 데이터 용량이나 전송 비용이 없어지는 것은 아닙니다. 원격 저장소의 접근 권한과 보관 정책도 필요합니다. LFS는 대용량 파일 추적을 돕고 DVC는 ML 데이터·파이프라인 재현까지 다루는 도구로 배웁니다.

## 적용 조건과 한계

Git 체크아웃은 메타데이터를 바꾸며 DVC 체크아웃은 캐시의 실제 내용을 작업 공간에 반영합니다. 필요한 내용이 캐시에 없으면 원격에서 가져와야 합니다. 환경·난수·외부 입력까지 고정하지 않으면 동일한 학습 결과는 보장되지 않습니다.

DVC가 추적하는 실제 데이터는 .gitignore로 Git 추적에서 제외합니다. .dvcignore는 DVC가 탐색하지 않을 경로를 지정하는 별도 파일입니다. 캐시는 내용 단위로 재사용하며 모든 바이너리의 변경 바이트만 저장한다고 가정하지 않습니다.

## 전체 과정과 연결하기

Git LFS는 Git 이력에 작은 포인터를 기록하고 실제 큰 파일은 별도 저장소에 보관합니다. 체크아웃한 포인터가 식별하는 내용을 가져오면 작업 공간에서 파일을 사용할 수 있습니다.
