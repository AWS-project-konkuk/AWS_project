## 개념 이해

Blue·Green은 기존 환경과 새 환경을 함께 준비한 뒤 요청 경로를 전환합니다. 새 환경이 준비됐는지 확인하고 전환하며 문제가 있으면 기존 경로로 되돌릴 수 있도록 합니다.

## 관찰한 결과 해석하기

두 환경을 유지하는 비용이 들고 데이터·외부 의존성의 호환도 확인해야 합니다. 여기서는 모델 요청 경로만 단순화해 준비→전환→롤백의 차이를 보여줍니다.

## 적용 조건과 한계

전송 프로토콜 선택은 모델 품질을 바꾸지 않습니다. Shadow는 새 모델의 응답을 사용자에게 보내지 않고, Canary는 일부 사용자에게 실제로 보냅니다. 전환과 승격은 별도 판단입니다.

## 전체 과정과 연결하기

기존 환경을 유지하며 새 환경을 준비하고 상태를 확인한 뒤 요청 경로를 전환합니다. 전환 뒤 문제가 있으면 이전 환경으로 경로를 되돌릴 수 있도록 준비합니다.
