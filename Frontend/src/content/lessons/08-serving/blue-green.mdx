## 새 서버는 준비 중인데 요청부터 옮겼습니다

모델 v2를 별도 서버에 띄워 둔 뒤 사용자 요청을 전부 옮겼습니다. 새 서버는 켜져 있지만 아직 모델 파일을 읽는 중입니다. 배포 화면에는 이미 v2인데, 고객에게 보이는 건 오류 화면입니다. 요청을 옮기기 전에 무엇을 확인해야 할까요?

## 개념 이해

Blue·Green은 기존 환경과 새 환경을 함께 준비한 뒤 요청 경로를 전환합니다. 새 환경이 준비됐는지 확인하고 전환하며 문제가 있으면 기존 경로로 되돌릴 수 있도록 합니다.

## 관찰한 결과 해석하기

두 환경을 유지하는 비용이 들고 데이터·외부 의존성의 호환도 확인해야 합니다. 여기서는 모델 요청 경로만 단순화해 준비→전환→롤백의 차이를 보여줍니다.

## 적용 조건과 한계

두 환경을 동시에 유지하므로 자원이 약 두 배 필요합니다. 전환이 한 번에 일어나서, 문제가 있으면 모든 사용자가 동시에 영향을 받습니다. 새 모델이 다른 피처 형식을 쓰면 롤백했을 때 기존 모델이 입력을 읽지 못할 수 있습니다.

## 전체 과정과 연결하기

기존 환경을 유지하며 새 환경을 준비하고 상태를 확인한 뒤 요청 경로를 전환합니다. 전환 뒤 문제가 있으면 이전 환경으로 경로를 되돌릴 수 있도록 준비합니다.
