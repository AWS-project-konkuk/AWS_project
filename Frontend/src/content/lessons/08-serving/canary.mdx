## ‘테스트 통과’ 스티커만 보고 전원에게 배포할까요?

새 추천 모델이 사내 테스트에서는 잘 맞혔습니다. 그런데 실제 고객의 기기와 요청은 테스트에서 본 것보다 다양합니다. 출시 버튼 한 번으로 전원이 새 모델을 만나게 하기 전에, 문제의 영향을 작게 유지하며 실제 응답을 확인할 수 있을까요?

## 개념 이해

Canary는 일부 실제 사용자 요청을 새 버전으로 전달해 영향을 제한하며 관측합니다. 지연·오류·품질을 확인하고 비율을 늘리거나 기존 버전으로 되돌립니다.

> **연결 전에 예측하기** — Canary는 실제 요청 일부를 새 모델로 보냅니다. 요청 복제만 하는 Shadow와 무엇이 다른지 생각해보세요.

<NodeExample />

연결을 따라가며 확인한 자료는 **실제 요청 90건 · 실제 요청 10건**입니다. 새 모델의 응답을 사용자가 받는다는 점을 고려해 비율과 중단 기준을 정합니다. 작은 표본의 수치만으로 전체 사용자 품질을 단정하지 마세요.

## 관찰한 결과 해석하기

Canary의 신규 모델 응답은 실제 사용자에게 전달됩니다. 비율을 낮춰도 영향이 0은 아닙니다. 이 활동은 100개 요청을 고정적으로 분배하며 통계적 품질 검증 전체를 재현하지 않습니다.

## 적용 조건과 한계

비율이 낮으면 문제를 발견하기까지 오래 걸리고, 작은 표본의 수치는 흔들릴 수 있습니다. Canary 응답은 실제 사용자에게 가므로 비율을 낮춰도 영향이 0은 아닙니다.

## 전체 과정과 연결하기

실제 사용자 요청의 일부를 새 모델로 보내면 영향을 제한하며 지연·오류·품질을 관찰할 수 있습니다. 관측 결과에 따라 새 버전 비율을 늘리거나 이전 경로로 되돌립니다.
