그림의 **기존 버전 중지**, **응답 공백**, **새 버전 시작**에 주목해 보세요. 기존 실행을 중지한 뒤 같은 자원에서 새 버전을 시작하면 배포 구성이 단순해집니다.

## 개념 이해

중단 배포는 기존 실행을 멈춘 뒤 새 버전을 실행하는 단순한 방식입니다. 자원을 재사용하기 쉽지만 새 버전이 준비되기 전까지 요청을 처리할 수 없는 구간이 생길 수 있습니다.

## 관찰한 결과 해석하기

지속적인 요청이 들어오는 서비스에서는 이 공백이 사용자 오류가 됩니다. 무중단 전환은 실행 준비 확인·요청 경로·롤백 등을 함께 설계해야 하며 전략의 이름만으로 장애가 없어지는 것은 아닙니다.

## 적용 조건과 한계

전송 프로토콜 선택은 모델 품질을 바꾸지 않습니다. Shadow는 새 모델의 응답을 사용자에게 보내지 않고, Canary는 일부 사용자에게 실제로 보냅니다. 전환과 승격은 별도 판단입니다.
