그림의 **야간 일괄 예측**, **실시간 요청**, **예측 결과**에 주목해 보세요. Batch는 데이터를 모아 정해진 때 예측하고 결과를 보관합니다.

## 개념 이해

Batch 서빙은 요청·데이터를 모아 정해진 시점에 일괄 예측합니다. Real-time 서빙은 개별 요청에 지연을 줄여 응답합니다. 다음 날 추천 목록을 만드는 작업과 지금 결제 요청을 판단하는 작업은 필요한 시점이 다릅니다.

| 방식      | 실행 시점        | 예시              |
| --------- | ---------------- | ----------------- |
| Batch     | 모아서 일괄 처리 | 다음 날 추천 목록 |
| Real-time | 요청마다 처리    | 지금 결제 판단    |

## 관찰한 결과 해석하기

Real-time이 항상 더 좋은 선택은 아닙니다. 지연 요구·처리량·운영 비용과 모델 실행 특성을 고려합니다. 아래 시간선에서는 같은 요청을 즉시 처리하거나 묶어 처리하는 차이를 비교합니다.

## 적용 조건과 한계

전송 프로토콜 선택은 모델 품질을 바꾸지 않습니다. Shadow는 새 모델의 응답을 사용자에게 보내지 않고, Canary는 일부 사용자에게 실제로 보냅니다. 전환과 승격은 별도 판단입니다.

## 전체 과정과 연결하기

Batch는 데이터를 모아 정해진 때 예측하고 결과를 보관합니다. Real-time은 개별 요청의 입력을 받아 그때 예측해 응답하므로 필요한 결과 시점과 허용 지연이 다릅니다.
