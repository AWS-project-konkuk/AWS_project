## 문제 상황

고성능 GPU로 모델을 학습하고 있지만 예상보다 학습 시간이 오래 걸립니다. 모니터링 결과 GPU 사용률이 계속 높게 유지되지 않고, 계산을 멈춘 채 기다리는 구간이 반복됩니다.

GPU 자체에 문제가 있는 것일까요?

모델 학습에서는 GPU가 계산을 시작하기 전에 다음 배치가 준비되어야 합니다. 저장소에서 데이터를 읽고 CPU에서 전처리한 뒤 GPU 메모리로 전달하는 과정이 느리면 GPU는 계산할 데이터가 없어 기다리게 됩니다.

예를 들어 GPU는 초당 100배치를 처리할 수 있지만 데이터 로더가 초당 30배치만 준비한다면 GPU 성능을 모두 사용할 수 없습니다.

**이번 학습에서는 GPU가 데이터를 기다리는 I/O starvation의 원인을 찾고, 데이터 공급 경로를 단계별로 개선하는 방법을 알아봅니다.**

## 개념과 동작 원리

### 1. 배치는 어떻게 GPU까지 이동할까요?

학습 데이터 한 배치는 보통 다음 단계를 거칩니다.

1. 저장소에서 원본 파일을 읽습니다.
2. 압축을 풀거나 이미지·텍스트를 디코딩합니다.
3. CPU에서 크기 조정과 변환 등의 전처리를 수행합니다.
4. 완성된 배치를 호스트 메모리에 준비합니다.
5. 배치를 GPU 메모리로 전송합니다.
6. GPU가 모델 계산을 수행합니다.

이 단계들은 하나의 공급 사슬처럼 이어집니다. 어느 한 단계라도 느리면 뒤의 단계는 기다리게 됩니다.

### 2. 어디에서 병목이 생길까요?

| 병목 위치       | 관찰할 수 있는 현상             | 확인할 항목                |
| --------------- | ------------------------------- | -------------------------- |
| 저장소·네트워크 | 파일 읽기에 오래 걸림           | 읽기 지연, 처리량, 요청 수 |
| 작은 파일 요청  | 파일 수가 늘수록 느려짐         | 객체 수, 메타데이터 처리   |
| CPU 전처리      | CPU는 바쁘지만 GPU는 대기       | worker 수, 디코딩 시간     |
| 메모리 전송     | 배치는 준비됐지만 전달이 느림   | 전송 시간, 메모리 사용량   |
| GPU 계산        | 데이터는 준비됐지만 계산이 느림 | 연산 시간, GPU 사용률      |

GPU 사용률만 확인해서는 정확한 원인을 알기 어렵습니다. 각 단계에 걸리는 시간을 나누어 측정해야 합니다.

### 3. 공급 속도를 어떻게 개선할까요?

- **병렬 데이터 로더**는 여러 배치를 미리 읽고 전처리합니다.
- **Prefetch**는 현재 배치를 계산하는 동안 다음 배치를 준비합니다.
- **Cache**는 반복해서 읽는 데이터를 가까운 저장 공간에 보관합니다.
- **Sharding**은 많은 작은 파일을 큰 묶음으로 구성해 요청 횟수를 줄입니다.

<Activity />

이 방법들이 항상 성능을 높이는 것은 아닙니다. worker가 너무 많으면 CPU와 메모리 경쟁이 생기고, 캐시는 첫 읽기에는 도움이 되지 않습니다. 한 가지 설정을 바꾼 뒤 같은 조건에서 다시 측정해야 합니다.

## 비교와 한계

- GPU를 늘리면 데이터 소비 능력도 커져 기존 공급 병목이 더 심해질 수 있습니다.
- 캐시 적중률이 낮으면 저장 공간만 사용하고 성능 이득은 작을 수 있습니다.
- shard는 요청 수를 줄이지만 일부 샘플만 임의로 읽는 작업은 불편해질 수 있습니다.
- 병렬 로더를 늘릴 때는 CPU, 메모리와 저장소가 감당할 수 있는지도 확인해야 합니다.
- 활동의 공급 속도는 개념 비교용 값이며 실제 개선 폭을 의미하지 않습니다.

## 전체 과정과 연결

Object Storage는 원본 데이터를 보관하지만 GPU에 배치를 자동으로 공급하지는 않습니다. 저장소에서 로더를 거쳐 GPU까지 이어지는 전체 경로를 측정해야 합니다.

>
> “GPU가 기다리는 시간은 저장소 읽기, CPU 전처리, 데이터 전송 중 어디에서 발생할까?”

## 핵심 정리

GPU의 계산 속도보다 데이터 공급 속도가 느리면 **I/O starvation**이 발생합니다. GPU를 늘리기 전에 배치 대기 시간을 측정하고, 저장소 읽기·작은 파일 요청·CPU 전처리·GPU 전송 중 가장 느린 단계를 찾아 개선해야 합니다.
