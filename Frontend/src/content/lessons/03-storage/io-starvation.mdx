## 개념 이해

GPU가 연산을 마쳐도 다음 배치가 준비되지 않으면 기다립니다. 디스크·네트워크 I/O, 작은 파일의 반복 조회, CPU 전처리가 원인이 될 수 있습니다. 먼저 어느 단계가 느린지 관측해야 합니다.

## 관찰한 결과 해석하기

캐시는 반복 조회를 줄이고 샤딩은 작은 파일의 요청 부담을 줄일 수 있습니다. 데이터 로더의 병렬 읽기는 공급을 늘릴 수 있지만 과도하면 메모리·CPU·스토리지 경쟁이 생깁니다. GPU 수만 늘리는 것은 데이터 병목의 직접 해결책이 아닙니다.

## 적용 조건과 한계

영구 볼륨은 백업이 아닙니다. 공유 읽기만 필요한지 동시 쓰기도 필요한지 판단하고 저장소·드라이버의 지원을 확인합니다. 캐시는 반복 읽기를 돕지만 최초 읽기나 잘못된 데이터 자체를 해결하지 않습니다.

## 전체 과정과 연결하기

저장소에서 읽고 CPU에서 전처리한 배치가 GPU에 도착해야 다음 연산이 시작됩니다. 읽기·작은 파일 요청·전처리·장치 전송 중 느린 단계가 전체 공급량을 제한합니다.
