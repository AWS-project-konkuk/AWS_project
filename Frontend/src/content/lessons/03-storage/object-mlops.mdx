그림의 **데이터셋 객체**, **학습 작업**, **모델 아티팩트**에 주목해 보세요. 큰 데이터셋과 모델 파일을 공통 객체 저장소에 두면 실행 서버를 교체해도 같은 키로 자료를 가져올 수 있습니다.

## 개념 이해

Object Storage는 대규모 데이터셋과 모델 아티팩트를 내구성 있게 보관하고 여러 작업이 같은 키로 접근하는 데 유용합니다. 연산 자원과 데이터 보관을 분리하면 작업을 교체해도 같은 데이터셋을 사용할 수 있습니다.

## 관찰한 결과 해석하기

객체 저장소 자체가 모든 학습 I/O를 가장 빠르게 만드는 것은 아닙니다. 원본은 객체 저장소에 두고 필요한 데이터를 캐시하거나 묶어서 읽을 수 있습니다. 보관 효율과 학습 중 공급 성능을 따로 판단하세요.

## 적용 조건과 한계

영구 볼륨은 백업이 아닙니다. 공유 읽기만 필요한지 동시 쓰기도 필요한지 판단하고 저장소·드라이버의 지원을 확인합니다. 캐시는 반복 읽기를 돕지만 최초 읽기나 잘못된 데이터 자체를 해결하지 않습니다.

## 전체 과정과 연결하기

큰 데이터셋과 모델 파일을 공통 객체 저장소에 두면 실행 서버를 교체해도 같은 키로 자료를 가져올 수 있습니다. 로더는 데이터를 읽어 학습에 공급하고 결과 모델을 다시 보관합니다.
