## 문제 상황

Kubernetes 환경에서 여러 Pod를 이용해 AI 모델을 학습하는 시스템을 구축하려고 합니다.

모델 학습 과정에서는 다음과 같은 데이터들이 사용됩니다.

- **학습 데이터셋**: 여러 학습 Pod가 동일한 데이터를 읽어야 합니다.
- **전처리 임시 파일**: 학습 과정에서 잠시 사용하며, 작업이 끝나면 삭제되어도 괜찮습니다.
- **모델 체크포인트**: 학습이 중단되더라도 이전 학습 상태를 복구할 수 있도록 보존해야 합니다.

처음에는 이러한 데이터들을 별다른 구분 없이 Pod 내부에 저장했습니다.

그런데 학습 도중 Pod에 문제가 발생해 새로운 Pod가 생성되자, 기존에 저장했던 데이터들이 사라졌습니다.

또한 여러 노드에서 동시에 모델을 학습시키려고 했지만, 한 노드에 저장된 파일을 다른 노드의 Pod에서 사용할 수 없는 문제도 발생했습니다.

그렇다면 이러한 문제를 해결하기 위해 모든 데이터를 하나의 저장소에 보관하면 될까요?

데이터마다 보존해야 하는 기간과 접근해야 하는 대상이 다르기 때문에 반드시 그렇지는 않습니다.

/>

예를 들어 임시 파일은 학습이 끝나면 삭제되어도 되지만, 모델 체크포인트는 Pod가 삭제되거나 다른 노드에서 다시 실행되더라도 유지되어야 합니다. 또한 학습 데이터셋은 여러 노드에서 동시에 읽을 수 있어야 합니다.

따라서 스토리지를 선택하기 전에 다음 두 가지 질문을 먼저 생각해 봐야 합니다.

### 1. 파일 수명(Lifecycle)

**데이터는 언제까지 보존되어야 할까요?**

- 컨테이너가 재시작되어도 남아 있어야 할까요?
- Pod가 삭제되고 새로 생성되어도 유지되어야 할까요?
- Pod가 다른 노드에서 실행되더라도 동일한 데이터에 접근할 수 있어야 할까요?

### 2. 데이터 공유 조건

**누가, 어떤 방식으로 데이터에 접근해야 할까요?**

- 하나의 Pod에서만 사용하면 될까요?
- 여러 Pod가 동일한 데이터를 읽어야 할까요?
- 서로 다른 노드에서 동시에 접근해야 할까요?
- 여러 Pod가 동일한 데이터에 쓰기 작업까지 수행해야 할까요?

이러한 조건을 고려하지 않고 스토리지를 선택하면 데이터가 유실되거나, 필요한 데이터에 접근하지 못하거나, 불필요한 스토리지 비용이 발생할 수 있습니다.

**이번 학습에서는 파일의 수명과 공유 조건을 기준으로 Kubernetes 환경에서 적절한 스토리지를 선택하는 방법을 알아봅니다.**

## 개념과 동작 원리
### 1. 파일 수명(Lifecycle)

파일 수명은 **어떤 작업이 중단되거나 다시 시작되어도 데이터를 보존해야 하는지**를 뜻합니다.

예를 들어 AI 모델을 학습할 때 전처리 중간 결과는 사라져도 다시 만들 수 있지만, 오랜 시간 학습한 **모델 체크포인트**는 사라지면 곤란합니다.

| 상황 | 어떤 일이 일어날까요? | 확인할 질문 |
| --- | --- | --- |
| 컨테이너 재시작 | 같은 Pod에서 컨테이너만 다시 만들어집니다. | 파일이 컨테이너와 함께 없어져도 될까요? |
| Pod 교체 | 기존 Pod가 삭제되고 새로운 Pod가 생성됩니다. | 새 Pod에서도 이전 파일을 사용해야 할까요? |
| 노드 교체 | 새 Pod가 다른 컴퓨터(노드)에서 실행됩니다. | 다른 노드에서도 동일한 파일에 접근해야 할까요? |

여기서 중요한 차이가 있습니다.

- **컨테이너의 쓰기 계층**에만 저장한 파일은 그 컨테이너가 교체되면 사라집니다.
- **Pod에 연결된 임시 저장 공간**은 컨테이너가 재시작되어도 남을 수 있지만 Pod가 삭제되면 사라집니다.
- **특정 노드의 디스크**에 저장한 파일은 Pod가 삭제되어도 그 노드에 남을 수 있지만, 다른 노드에서 자동으로 보이는 것은 아닙니다.
- **Pod와 독립적으로 관리되는 저장 공간**을 사용하면 Pod 교체 후에도 데이터를 다시 연결할 수 있습니다. 다만 실제 보존 범위는 저장 방식과 설정에 따라 달라집니다.

따라서 **파일이 언제 사라져도 괜찮은지**를 먼저 판단해야 합니다.

### 2. 데이터 공유 조건(Access Requirements)

파일이 오래 남는 것만으로는 충분하지 않습니다. **어떤 Pod가 그 파일에 접근할 수 있어야 하는지**도 알아야 합니다.

예를 들어 여러 노드에서 AI 모델을 분산 학습한다면, 여러 학습 Pod가 같은 데이터셋을 읽어야 할 수 있습니다.

| 공유 조건 | 예시 | 필요한 기능 |
| --- | --- | --- |
| 하나의 Pod만 사용 | 해당 Pod의 전처리 임시 파일 | 해당 Pod에서 읽기·쓰기 |
| 여러 Pod가 함께 읽기 | 공통 학습 데이터셋 | 여러 Pod에서 동일 데이터 읽기 |
| 여러 Pod가 함께 읽고 쓰기 | 공동으로 기록하는 학습 결과 | 여러 Pod의 쓰기 접근 및 충돌 방지 |

여기서 **읽기(Read)**는 파일 내용을 확인하거나 가져오는 것이고, **쓰기(Write)**는 파일을 생성하거나 수정하는 것입니다.

여러 Pod가 같은 파일을 읽는 것은 비교적 단순하지만, **동시에 같은 파일을 수정**하면 내용이 덮어써지거나 충돌할 수 있습니다. 따라서 접근 가능 여부뿐 아니라 쓰기 작업을 어떻게 조정할지도 고려해야 합니다.

또한 **같은 노드에 있는 여러 Pod가 접근하는 것**과 **서로 다른 노드에 있는 Pod가 접근하는 것**은 다른 요구사항입니다.

## 비교와 한계

파일 수명과 공유 조건은 서로 다른 질문입니다.

- 파일이 **오랫동안 보존**되더라도 다른 노드에서는 접근하지 못할 수 있습니다.
- 파일을 **여러 Pod가 공유**하더라도 삭제나 장애에 대비한 백업이 자동으로 보장되는 것은 아닙니다.
- 여러 Pod가 **동시에 쓸 수 있는 것**과 데이터가 **충돌 없이 안전하게 갱신되는 것**은 다릅니다.

## 전체 과정과 연결

스토리지를 선택하기 전에 다음을 결정합니다.

1. **파일 수명** — 컨테이너·Pod·노드가 교체되어도 남아야 하는가?
2. **공유 조건** — 하나의 Pod만 사용하는가, 여러 Pod나 노드가 함께 사용하는가? 읽기만 하는가, 쓰기도 하는가?

이 두 가지 요구사항을 정의했다면, 다음 단계에서 **Block, File, Object Storage**의 특징을 비교하여 알맞은 저장 방식을 선택할 수 있습니다.

> **판단할 때 확인하기**  
> “이 데이터는 어떤 장애 이후에도 남아야 하고, 어떤 Pod가 읽거나 수정해야 할까?”

## 핵심 정리

**파일 수명은 데이터의 보존 범위**, **공유 조건은 데이터에 접근하는 대상과 방식**을 결정합니다. 두 조건을 먼저 파악해야 데이터 유실과 접근 불가 문제를 줄이고, 상황에 맞는 스토리지를 선택할 수 있습니다.
