## 문제 상황과 전체 맥락

데이터를 디스크처럼 읽을까요, 객체로 읽을까요? 저장소의 형태와 요청 크기를 함께 비교합니다.

그림의 **Block**, **File**, **Object**에 주목해 보세요. Block은 디스크 블록, File은 파일과 디렉터리, Object는 키와 메타데이터를 중심으로 접근합니다.

## 개념 이해

Block은 디스크의 블록 단위로 접근하며 보통 파일 시스템 위에서 사용합니다. File은 파일·디렉터리와 공유 경로를 제공하고 Object는 키와 메타데이터를 통해 객체 단위로 접근합니다. 어느 하나가 모든 작업에서 가장 빠르지는 않습니다.

| 종류   | 접근                  | 사용 예               |
| ------ | --------------------- | --------------------- |
| Block  | 블록 주소·파일 시스템 | OS·디스크             |
| File   | 파일 경로·디렉터리    | 공유 파일 작업        |
| Object | 버킷·객체 키          | 원본 데이터·모델 파일 |

## 관찰한 결과 해석하기

작은 요청을 많이 보내면 요청당 지연의 비중이 커집니다. 큰 순차 읽기는 처리량이 중요해집니다. 아래 수치는 비교용 가정이며 실제 서비스·네트워크·캐시·병렬성에 따라 결과가 달라집니다.

## 적용 조건과 한계

영구 볼륨은 백업이 아닙니다. 공유 읽기만 필요한지 동시 쓰기도 필요한지 판단하고 저장소·드라이버의 지원을 확인합니다. 캐시는 반복 읽기를 돕지만 최초 읽기나 잘못된 데이터 자체를 해결하지 않습니다.

## 전체 과정과 연결하기

Block은 디스크 블록, File은 파일과 디렉터리, Object는 키와 메타데이터를 중심으로 접근합니다. 프로그램이 요구하는 접근 방식에 맞춰 저장소와 읽기 경로를 구성해야 합니다.
